Privacy Policy

Effective October 11, 2026. Applies to the 300-3000 self-operated notification application.

1. Purpose and account access

300-3000 monitors selected public blockchain information. When the account owner enables its optional Gmail notification channel, the local application authenticates to the account owner's Gmail account with Google OAuth. It uses Gmail to send notifications and to search for and retrieve matching messages from the Sent folder to confirm delivery, prevent duplicates and reconcile uncertain results. The application does not need to scan the inbox for this workflow.

2. Data used

The local installation may process the authorized Gmail account identity, OAuth access and refresh credentials, outgoing message subjects and contents, unique notification identifiers, matching Sent-message contents and labels, Gmail message/thread identifiers, and delivery timestamps. Notification contents may include token contract addresses, public blockchain transactions and locally calculated trading-signal observations.

3. Storage and retention

The account owner controls the machine running the software. OAuth credentials are read from a local credential file. Notification events, rendered message contents, and Gmail delivery receipts are stored in local SQLite records for reliability and auditing. These records can persist until the account owner deletes them according to the local application's maintenance and backup procedures. They are not automatically removed when Google consent is revoked.

4. Sharing, advertising and security

300-3000 does not use Google user data for advertising, sell Google user data, or provide it to data brokers. Gmail communications are transmitted to Google to perform the requested Gmail operations and to the configured notification recipient as directed by the account owner. The OAuth credential file must not be published in Git or shared with third parties. The application uses owner-managed local access controls. This public information website does not embed advertising or analytics scripts.

5. Limited use

Google user data is accessed and used only for the account owner's authorized notification and delivery-reconciliation functionality. The application does not use Gmail data to train generalized AI models or for unrelated research, advertising, or profiling.

6. Withdrawal and deletion

The account owner can revoke the application's Google access through Google Account third-party connections and stop or disable the existing local Gmail notification service. To remove stored data, delete or rotate local credential files and the locally maintained notification database and backups under the owner's control. Revoking OAuth access alone does not delete existing local records.

7. Contact and updates

Questions about the application can be raised via the project issue tracker or the support email shown on the application's Google OAuth consent screen. This policy will be updated if the application's handling of Google user data changes.
