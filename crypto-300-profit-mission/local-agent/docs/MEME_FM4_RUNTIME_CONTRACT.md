# Meme FM4 deterministic runtime and external GPT contract

Meme is the system; Frank is person_id=frank. The only live registry member is explicitly user-approved Frank. Each person can have multiple verified Solana wallets. Wallet membership is unique; consensus counts unique person_id, never wallet count. Additional user-approved people default OBSERVE_ONLY; verified OBSERVE_ONLY may participate in TOKEN_CONSENSUS. Enabling another person's PERSON_PATTERN requires USER_ACCEPTED_HISTORY_REPLAY and an evidence hash, not a copied Frank threshold. The live registry file is config/meme_person_registry.json. No code discovers or adds people.

The collector reuses official Solana finalized jsonParsed RPC, frank-v7 normalization, durable first-detection raw journal and SQLite cursor. Frank's existing forward.sqlite, raw cache and real observation/candidate/batch history are retained in place. Additional approved wallets use separate source SQLite/cursors under meme-wallets/<wallet-hash>, avoiding signature collisions across wallets; their initial finalized boundary seeds no forward observation. Only subsequent real forward observations create facts. Primary Frank history feature reads are bounded to500 records, source processing256 observations/cycle, recent signal aggregation1000 facts. Bounds fail closed; they do not alter historical audit evidence. Raw source transactions are not rewritten.

FM4 migration is additive: meme_meta, meme_source_observations, meme_facts, meme_signals, meme_runs, meme_decisions, meme_mail_outbox, meme_mail_signals, meme_transport. Schema hash/version fail closed on drift. Before the scanner rename, all existing source observations become BASELINE_EXCLUDED. They cannot become new Meme live signals. Runtime recovery uses source acknowledgements atomically with facts/signals/runs; a crash before commit retries, a committed observation never regenerates a fresh identity. Existing Frank queue/outbox/transport remains preserved; its legacy batch prefix is not a declaration of synthetic payloads.

Candidate V2 facts include verified person/wallet, chain/mint, positive owned net token amount/decimals, net debit assets, finalized slot, signature/block time, first-detected/normalized/created times, source raw/evidence hashes, available-history behavior and explicit unavailable reasons. Behavior first_entry/add/reentry is scoped to observed referenced accounts and at most500 prior causal source records, never a lifetime claim. Token quantity is not assumed swap cost. USD, liquidity, market cap, executable price, token creation time and comparable buy-size percentile remain null with reasons when unavailable. Future labels never enter online facts. Canonical payload_sha256 is the transport hash.

PERSON_PATTERN is a deterministic feature handoff, not an investment SEND. TOKEN_CONSENSUS groups qualifying buys by exact mint and causal explicit window; current default900 seconds, supportable comparison windows300/900/1800/3600/10800 seconds. No incremental edge is assumed. The current single-person live registry correctly yields zero consensus.

TTL is config/meme_shadow_policy.json: TEMPORARY_SHADOW_TTL900 seconds from first_event_at, rationale/evidence/created_at explicit. This is shadow policy, not calibrated strategy or production validation. At now>=expires_at, render and pending delivery claim permanently refuse investment delivery. A late readback can recognize a previously accepted mail, but never issue a late retry. The hourly external GPT consumer may discard every candidate if it sees it after TTL; this path is not claimed to be real-time follow trading.

Stable identities are derived from namespace, person/wallet, transaction, mint, signal family and underlying event IDs. run_id hashes sorted immutable candidate identities/facts; candidate IDs rebind to that run/source_batch_id without changing signal identity. decision_id is meme:decision:SHA256({run,signal}); mail_run_id hashes run and selected signals; content_hash covers HTML. Published facts/run files cannot change. SQLite UNIQUE constraints and BEGIN IMMEDIATE protect facts, signals, decisions, mail identities and signal-to-mail assignment across crashes/concurrent workers.

## Private Git handoff

Reuse lxxlx2/crypto-monitor-runtime only, existing mac-data branch for local facts. LIVE namespace:

- runtime-v2/meme/runs/<run_id>/candidate-bundle.json
- runtime-v2/meme/runs/<run_id>/renderer-input.json
- runtime-v2/meme/runs/<run_id>/transport-receipt.json
- runtime-v2/meme/manifest/current.json

TEST namespace: runtime-v2-test/meme/<test_id>/..., with namespace=TEST in every bundle and deterministic fixture. The live consumer must reject TEST rather than relabel it. Before any LIVE network write, schema/hash/namespace and durable real observation/raw normalization/amount binding are checked. Empty LIVE startup bundle contains no candidate and explicitly means NO_CURRENT_SIGNALS; it proves transport connectivity without replaying FM3's old ACTIVE. A new live candidate requires a new real post-migration observation.

Run files publish immutably with exact canonical readback. Only after all files verify does current.json publish via blob-SHA CAS. It is a pointer, not a mutable run. Sequence comes from durable SQLite rowid; pointer rollback or equal-sequence/different-run fails closed. Identical republish writes zero changes. Bounded retry and ambiguous PUT readback reuse the verified private Git implementation. No audit retention deletion is performed in FM4.

## External GPT decisions and renderer

$300-3000 is an external downstream GPT consumer; Codex does not call it or modify its schedule. GPT decides SEND/NO_SEND and performs current project/social/liquidity/risk enrichment. It must not reconstruct deterministic person, BUY/SELL, mint, amount or multi-person facts. A current decision must include schema_version2, namespace, stable decision_id, run_id, signal_id/type, person_ids, mint, decision, reason_codes/evidence/risks arrays, followable_now boolean, confidence HIGH/MEDIUM/LOW, decided_at and exact integer candidate_age_seconds measured from first_event_at. Decision time must not precede candidate creation or be in the future. SEND requires evidence, followable_now=true and unexpired candidate. NO_SEND decisions are still immutable audit records.

The gpt-data branch may hold runtime-v2/meme/decisions/<run_id>.json and delivery receipts if the external connector can write reliably. Connector writeback and actual ChatGPT task integration were not mutated or simulated as real GPT decisions in FM4. Source bundles remain immutable; provider capabilities must be verified by that external task. No new API/scheduled task is created here.

Renderer input is only the current run, its validated decisions and enrichment {run_id,status:SUCCESS,by_signal}. No previous HTML/report/cache file is read. Text is HTML-escaped. Empty family sections disappear; no SEND means no email artifact/outbox. Same mint across families produces one block under TOKEN_CONSENSUS, with pattern reasons attached; distinct mints remain. Facts and amounts within a block deduplicate by event_id.

MailOutbox.prepare persists current decisions and one immutable mail identity/content hash. claim atomically changes PENDING to INFLIGHT only before expiry. A crashed INFLIGHT send is uncertain: downstream must search Gmail Sent by mail_run_id/content_hash and read back exactly. One exact match marks SENT; missing/ambiguous matches remain UNCERTAIN, never blind resend. This is a fail-closed at-most-one identity policy; uncertainty may block delivery rather than risk duplicates. The implemented delivery executor is TEST-only and has no Gmail connector/client. Real Gmail belongs to $300-3000, and REAL_GMAIL_E2E remains NOT_YET_OBSERVED until separately verified.

## Local migration / rollback

scripts/meme_local_migration.py --root <existing-Frank-shadow-root> --evidence <new-private-migration-directory> records pre-migration-state.json, SQLite/raw/detection/config/receipt snapshots, migration-before.json, migration-after.json and restart-after.json. Old Frank must be exactly one RUNNING scanner with healthy cursor/integrity. Old agent is booted out and its scanner plus historical worker must exit before Meme is bootstrapped. Both services use the same fcntl service.lock and durable SQLite. Old plist is archived privately; only com.jerson.crypto-monitor-meme-shadow remains installed/enabled. Post-start polling, exact private handoff, monotonic cursor/counts, no old candidate replay, integrity/gap/dedupe and one controlled restart are required. On any failure, boot out Meme and restore/enable/bootstrap the saved Frank plist; do not reset SQLite to an older snapshot or discard newly committed evidence. The backup is recovery evidence, not an automatic destructive restore.

Monster, NFT and Core Price logic/data/runtime are untouched: DEFERRED_NOT_CANCELLED. Production trading, wallet actions, real Gmail sends and scheduled-task mutations are zero. FM4 stops for review; no FM5 starts automatically.
