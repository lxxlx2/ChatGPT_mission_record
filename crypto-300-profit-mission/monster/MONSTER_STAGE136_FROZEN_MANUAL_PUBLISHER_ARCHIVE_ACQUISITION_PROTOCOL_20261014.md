## Frozen acquisition contract

1. Inputs: Stage133 `--t0` JSON, optional Stage134 `--arrival-candidates` JSON, `--archive-root` corresponding to Stage135, optional `--out` machine manifest. Always revalidate raw Stage133 three-HTTPS receipt and Stage134 venue/population ledger before constructing a plan; never use names inferred from later winners.
2. Source days: exactly the union of Stage135 `required_days` for each start and in-window candidate through the frozen seven-day end. T0 symbols require 24h pre-window warmup, new candidates require contiguous minute sources from their declared first minute, which remains unverified as a real listing time. Preserve attempts and report unverified origin. Source URLs only Stage130 frozen `https://data.binance.vision/data/futures/um/daily/klines/<symbol>/1m/<symbol>-1m-YYYY-MM-DD.zip` plus official `.CHECKSUM`, using Unicode-safe exact-symbol URL escaping.
3. **Default plan/read-only mode** cannot call network or write archives. Actual fetch requires both a `--fetch-manual` switch and a separate file `--capture-request` with `schema=MONSTER_STAGE136_USER_REQUESTED_ONE_SHOT_V1`, `explicit_manual_request=true`, `allow_official_historical_publisher_fetch=true`. This is a caller attestation, not proof a human actually requested in chat; operator must verify actual authorization independently. No time-triggered execution, background launchd, GitHub scheduled workflow, implicit retries for future work, notifications or order execution.
4. Refuse actual fetching before the whole seven-day window has ended and an additional 48-hour conservative publisher preparation margin has elapsed. This only checks temporal readiness, **not** publisher publication guarantees; 404/timeout is recorded as not downloaded, not a no-signal/negative case. Do not catch digest, ZIP/member or invalid candle errors and silently continue. Existing valid ZIP+CHECKSUM pair is revalidated and skipped without downloading; an existing corrupt archive fails closed and is preserved for forensic review. Missing one of a pair is repaired in a controlled temporary/staged write, with no corrupted committed final pair.
5. Fetch official zip + checksum only for missing pairs, with Stage130 byte-size limit and original `verified_day` parser and original publisher checksum matching BEFORE writing to fixed archive paths. To avoid partial writes, stage files in a temporary folder in the same archive root, then atomically replace verified files; optional user-requested per-invocation file budget bounds runtime, leave residuals explicitly pending, no silent truncation. Whole-run manifest counts planned, verified reused, newly fetched, pending, and failed (source unavailable) symbols/days, without converting any missing data to model failure or adding future confidence.
6. The already frozen Stage135 audit remains the sole G0 minute completeness scorer. After files are acquired by an authorized operator, Stage135 separately checks full population, missing/censored 1m and replays only once genuinely available. Archive fetching alone never upgrades G0 issuer proof, full in-window listing census, G1 OOS validation, D1 priority or G4 net profitability.
