# ADR-005：Monster Spot D1 新候选单一预注册（BTC 相对强弱与最后一根 5m 确认）

**预注册时间**：2026-10-24，Asia/Bangkok 19:12 后；**状态**：RESEARCH_CANDIDATE_FROZEN_BEFORE_ANY_NOVEMBER_SOURCE_READ / NOT_VALIDATED / NO_DEPLOY。独立于现有 Stage77 G0–G6 阈值，不修改原 `monster_v4_shadow.py`、D0、FIFO8/Fair8 和 Stage166 旧回放。

## 0. 形成假设之前已经曝光的样本

历史已曝光（不得用来声称新策略样本外）：2025-07-01 BSC 源专项、Stage39/40/49/65/70/74/75/445 等旧样本，以及 2026-10-16..23 的 Binance Spot511 原Publisher 1m，T0 于2026-10-17T22:04:40Z冻结，真实 D0/D1 4,088/4,599 日档案、2,919/3,360全覆盖轮次、53 WATCH、46 SETUP、41普通crypto+3 Chiliz fan+2 bStocks。42旧 SETUP 原SQLite ID已经严格对账，Fair8对FIFO无新增。回放内候选币 60m 后中位走势和配对BTC对照均显示追涨后相对弱势，是**已暴露、仅用于设计假设**的事后诊断（见原证据，不据此拟合阈值）。

未知的2026-10-24完整官方日档案仍须先用于**旧策略的固定七日源/事件验证**。本ADR候选不得拿该日作为未看过的独立验证：它属于已经冻结的T0源观察窗口。

## 1. 只提出一套可证伪候选：D1_RBTC15_LAST5_V1

- **D0原样**：保留原市场、全511 T0名单、原Watch及入队、原3m触发、15m截止与原候选池，原计算和旧版本SQLite均不受本候选影响。
- **D1原规则必先通过**：与 `monster_v4_shadow.evaluate_closed_5m` 完全相同的**六根连续且真实闭合**5m币种K线，末三根上涨至少2根、末15m对前15m中位数成交额比>=1.5、末收盘价>=第3根收盘价。无论新候选是否通过，原规则实验结果都要并排保留。
- **新条件1：币种对BTC最近15分钟相对强弱>=0**：同一场所 `BTCUSDT` 与候选币的相同六根已闭合UTC 5m，参考价均为第3根5m收盘价（索引2），终点均为第6根5m收盘价（索引5）；对数以外的简单回报 `coin[5].close/coin[2].close - btc[5].close/btc[2].close >= 0`。零阈值是市场基准本身，不由已曝光46条最优筛选。
- **新条件2：币种最新5m未下跌**：`coin[5].close >= coin[4].close`（对照原D1的`2/3`上涨原则增加末次确认）。不得等待下一根未来K线，两个条件使用和原D1**相同已闭合六根**；不得对原WATCH从前面补上一条更早的伪SETUP。
- **数据缺失必须`SOURCE_CENSORED`**：只要任一根币/BTC K线缺失、时间错位、超前、未闭合、成交额无效、币种身份未确证，就不能标为新候选负例，更不能以BTC=0替代。BTC本身不可作为Monster目标；BTC作为基准的6根必须全有效。
- **状态机语义**：相同原WATCH episode+deadline内，原引擎可在每根新闭合5m上重新尝试本独立比较器；首次同时满足时记独立`D1_RBTC15_LAST5_SETUP`；始终没满足则`NO_SETUP_BEFORE_DEADLINE`或源删失`UNSCORED`。不延长15min截止、不硬每天5条截断、不覆盖原`SETUP_ACTIVE`、不偷偷丢原D0。
- **安全界限**：候选只标`RESEARCH_SETUP_NOT_BUY`。G4仍需账户资格、当时买入ask、退出bid、手续费滑点与明确名义金额；任何缺失只写UNKNOWN。无实盘单、自动任务、Gmail、Mac/Frank、BSC运行变更。

## 2. 确定先后执行和未曝光验证

前瞻评估必须提前冻结3个**彼此不重叠**的UTC完整七日研究窗口（不能按结果好坏挑日期），分别为：

1. `2026-11-02T00:00:00Z` 到 `2026-11-09T00:00:00Z`（未来）。
2. `2026-11-16T00:00:00Z` 到 `2026-11-23T00:00:00Z`（未来）。
3. `2026-12-01T00:00:00Z` 到 `2026-12-08T00:00:00Z`（未来）。

各需独立确定对应窗口T0（不能沿用10/17冻结511冒称以后同样上市），向前一整日1m源支撑24h成交额代理、向后七日支撑G1的2×未来标签、可能更长D2退出观察。官方ZIP、CHECKSUM及历史时间身份不足则该窗口`SOURCE_BLOCKED`，**不替换为已看过或表现有利的日期**。无后台计划/自动化授权；以后用户主动对话时才执行有限公开只读采集和离线回放。三个时间窗满足的是独立日期设计条件，而不是已满足G1“>=20独立2×事件”的样本数。

## 3. 事先固定验收、判败与对照

- 原始D0早期发现率G1：独立2×事件>=20、>=3时段、strict提前>=90%、提前>=5m>=85%，并披露5×/10×；零/少事件标`UNDERPOWERED`。
- G2：对D0提前>=5m的2×事件，新D1至少提前5m并覆盖>=80%；历史5×/10×漏报及冷启动/多场所各单列，任何满足G3而损坏G2的方案**REJECTED**。
- G3：原始D0全保留、新候选真实升级完整日均<=5/日、峰值<=12，不用通知配额硬截断；不得因账户Monitoring Tag答题资格扣除原D1注意力（G4另算）；Chiliz粉丝token独立分层，bStocks证券排除。源缺失日/时间片不可作为零事件。
- G4：>=30个相互独立的完整双侧真实买入/退出证据才能作初步净盈利推断；缺真实价差/盘口/金额=UNKNOWN，Minute OHLC路径和未来HIGH不得冒充买卖可成交盈利。
- G5：严格保持原 `monster_v4_shadow.py`、原FIFO8/Fair8作为baseline，新增研究旁路`D1_RBTC15_LAST5_V1`不得修改旧模型/原回放；真实另AI独立review（固定SHA）、复现、回归、时钟、负例、样本泄露审查。不达即`NOT_DONE`。
- G6：只要任一门禁不通过继续`NO_GO`，不部署、不合并、不改Frank、不发Monster真邮件、不建schedule、不交易。

这不是承诺策略收益。若新规则减少 G3 负载但损失早期2×发现/G2召回，或币种比BTC弱时仍产生大量追涨误报，应记录`REJECTED`，不能返回上述曝光样本拟合参数（需要新的独立提案和**新的未见日期**）。预注册确认前不得读取未来窗口数据，验证可开始日期以发布方确实发布并通过SHA为准。
