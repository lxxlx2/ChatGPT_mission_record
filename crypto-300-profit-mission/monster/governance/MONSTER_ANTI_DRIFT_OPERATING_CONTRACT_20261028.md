根因不是规则缺失，而是：**判定止损的人就是被止损的人**；**进度用活动量而不是用唯一问题的答案衡量**；**工程投入先于"鱼塘里有没有鱼"的证据**。

## 1. 唯一问题（UQ）

> 面向 **DEX / Launchpad 妖币**，在代币首次达到公众当时可观察、普通投资者可双向执行的交易准入时，仅用该时刻可见信息，能否提前筛选出未来 30/90 天存在**固定研究金额费后实际可卖出 5×/10×** 机会的子集，并使按事前冻结买入延迟和退出规则计算的净收益优于**同一合格母体**的随机选择？

所有工作必须能用一句话说明它如何推进 UQ 的答案。说不出来的工作不做。

UQ 的答案只允许四种：`YES_WITH_EVIDENCE` / `NO_REJECT` / `INSUFFICIENT_DATA` / `NOT_YET_TESTED`。当前答案：`NOT_YET_TESTED`。

## 2. 角色分离（核心机制）

| 角色 | 承担者 | 权限 |
|---|---|---|
| 建造者 Builder | 主开发对话（GPT） | 写代码、跑实验、提交 Git、提议 |
| 验收者 Acceptor | **另一个独立对话**（Claude 或 Codex，每周固定一次） | 只读仓库和周报，只回答第 5 节的 7 个问题，不写代码 |
| 决策者 Owner | 用户 | 只在周报上签三个字之一：`继续` / `转向` / `停止` |

硬规则：
- Builder **不得**修改本文件、不得新建或修改任何 ADR 的止损条款、不得修改 `budget.json`。本次 OWNER 批准的 PROPOSED→ACTIVE、纠正 P0 选择偏差及首次建立预算属于**唯一启动例外**；后续只接受用户本人提交或用户在周报上明确写出的指令。CI 文件和预算更改同样不得被 Builder 当成可自行授权的通道。
- Binance Alpha 仅可作为发生在决策时点之前的**辅助证据**，不得作为默认买入母体、主线或事后泄漏标签；严禁以 Alpha 公告替代 DEX 首次成交时点。用户没有批准转向 Alpha。
- Builder 的任何"我认为应该调整目标/止损/预算"只能写进周报的"提议"栏，不得直接执行。
- Acceptor 每周只审一份文件（第 4 节周报），不审代码细节；代码细节审核改为按阶段一次（见第 6 节）。

## 3. 机械预算（CI 强制，不可对话绕过）

文件 `crypto-300-profit-mission/monster/governance/budget.json`。现有 Monster CI 对本 PR 分支每次 push 的预算使用作**失败即拒绝验收**检查；超限 CI 红，Builder 必须停止追加研究提交并由 Owner 决策。CI 本身不阻止 Git push；若无受保护分支的**必需状态检查和 Owner-only 合并/规则变更权限**，不能声称预算技术上不可绕过。不得自行新增 workflow 或设置定时任务：


为什么用机械数：Builder 擅长把每一次"再多一个脚本"论证成必要。数字不接受论证，只接受用户改 json。

## 4. 周报（唯一进度载体，固定模板，不得增删栏目）

文件：`crypto-300-profit-mission/monster/governance/weekly/YYYY-MM-DD.md`，每周的周一 UTC 为文件名，**仅在用户主动交互/批准本周工作时**由 Builder 生成，≤60 行；不得建立 cron、schedule、Automation 或后台周一推送。缺报按未提交证据处理，不伪造周期报告。

```
## UQ 当前答案：NOT_YET_TESTED | INSUFFICIENT_DATA | NO_REJECT | YES_WITH_EVIDENCE
## 本周唯一指标（第 5 节定义的那一个数）：<数值或 NOT_MEASURED>，上周：<数值>
## 本周做了什么（≤5 行，每行必须以"为了回答 UQ 的 X 部分"开头）
## 本周没做什么 / 卡在哪（≤3 行，用 BLOCKED_BY_<原因>）
## 预算使用：commits N/40，新脚本 N/3，新文档 N/2，workflow N/0
## 止损检查：<第 7 节每条，逐条写 TRIGGERED / NOT_TRIGGERED>
## 提议（Builder 想改目标/止损/预算的，写这里，不执行）
## 请用户签：继续 / 转向 / 停止
```

用户每周只需读这一份、签一个词。看不懂或 Builder 没按模板写 → 默认签 `停止`，直到补齐。

## 5. 唯一指标与验收 7 问

**每阶段只有一个数字指标**，Acceptor 每周只核这一个数是否真实。

| 阶段 | 唯一指标 | 门槛 |
|---|---|---|
| P0 Kill Test | **N_VALID**：事前冻结母体规则、可核首个双向交易时点、as-of 特征及研究金额退出可评估性均明确的有效样本数 | **N_VALID ≥30**；不按最终涨幅强制配比，未达到来源/PIT/退出门槛的样本不计入 N_VALID |
| P1 Lift | 候选规则 top-k 与同母体随机 top-k 的净收益差（bootstrap 95% 下界） | 下界 > 0 |
| P2 Paper | 前向纸面 30 天，按冻结规则，扣费后净收益 | > 0 且回撤可接受 |
| P3 Micro-Live | 用户授权的极小真实金额，实际成交净收益 | 与 P2 偏差可解释 |

Acceptor 的 7 问（只答 YES/NO/UNKNOWN + 一行证据）：
1. 周报的唯一指标数值能否在仓库里复现？
2. 本周所有工作是否都指向 UQ？列出不指向的。
3. 预算是否超限？
4. 是否有任何"止损被重新解释"的迹象（新 ADR、新 Stage、目标措辞变化）？
5. 是否有任何活动量（commit/测试/审核次数）被当作进度表述？
6. 母体是否按事前时间/场所/身份规则包含全体符合资格的新币与死币，未按事后赢家/归零比例挑选、替换或缩分母？
7. 建议用户签：继续 / 转向 / 停止，一句话理由。

## 6. 阶段顺序：先杀后建

### P0 Kill Test（≤ 2 周，截止 2026-11-11T00:00:00Z，零代码优先）

**对象只有 DEX/Launchpad 妖币首次可买且可卖的早期机会**，BSC 为来源试点；其他链只在具备各自真实合法来源时独立列示，不把不同来源混为同一完整母体。Alpha / CEX 后续上币只能作不泄漏的辅助注释，不能让历史 Alpha 赢家替代早期发行的完整样本。

**先证来源，再定母体，不用事后涨幅抽样。** 研究时间候选为 2025-07～2026-03，但实际子窗口、精确链/Factory/Launchpad、所有符合资格和失败事件的来源清单、固定随机种子 `MONSTER_P0_20261028_V1` 与选择顺序必须在查询未来涨幅前登记。仅从同一个未删减原事件母体按创建/首次可交易时间或冻结种子抽取连续 30 例；不得为了凑 ≥5 个赢家、≥15 个失败者而事后挑币/替换。退市、没流动性、不可卖、没有价格/未获得数据均留下分母和原因。可另行**标为探索性**查看已知 10×/归零案例，但不能混入无偏 30 例，不可用于基准率/预测胜率。

手工最小验证（新代码/工作流=0 优先）：
1. 每例保留 token CA、精确场所/池、原始事件+链上区块/交易证据、公众可得时点的证据级别；`chain_event_at`、2026 回溯取得时点 `ingested_at` 与实际 `available_at` 分开。无 contemporaneous 时钟不标 `PIT_VERIFIED`，而标 `RECONSTRUCTED_ONLY` 或 `UNKNOWN`，并不得计入原 2025 PIT 门禁。
2. 首次真实双向交易后最多 1 小时内 ≤10 个事前可见特征：每个字段标来源和可得性；`NOT_PIT` 不回填“当时可见”；后续 Binance Alpha/价格高点/当前 holders 禁止入模。
3. 固定研究金额**仅作为研究假设而非用户交易金额授权**；买入时间/报价、全部真实卖出容量/税费/滑点/Gas、未上市/失效/迁池等成本或缺失原因必须完整列示，不能用事后 OHLC 最高价充当可卖出 10×。
4. P0 只输出一份冻结母体表（可修订同文件）和 `N_VALID`；观察高倍币、普通币、死币早期特征是否**值得**进入 P1，属于探索性判断。单凭肉眼分离、30 个样本或挑中事后赢家都**不构成信号盈利 PASS**，不允许将“无肉眼差异”写作统计性 `NO_REJECT`。
5. 若无法取得含失败事件的可核查完整来源/PIT/双向退出证据，P0=`INSUFFICIENT_DATA`，按截止停止这一**来源/假设**，不得开发观察器补源、变更日期或降低合格计数。只有来源成立且规则在扩样前冻结并获 Owner 的 `继续` 批准后，才可进入 P1。

**两个不相互替换的硬停止：**
- 原 ADR-006 **2026-11-02**：冻结 **2025-07-01 BSC 历史 P0** 的原 30/24/18 标准；无合格源就标 `SOURCE_BLOCKED / REJECT_INSUFFICIENT_PIT_COVERAGE` 并停止原历史路径，不能“转入新 P0”逃避截止。
- 本新方向 **2026-11-11T00:00:00Z**：若 `N_VALID <30` 或无法证明来源/可执行性，按本新 P0 结为 `INSUFFICIENT_DATA / PHASE_FAILED`，**不得延期**；只有 Owner 明确写 `转向：<新妖币发现假设>` 才允许另启。两者都不授权付费、自动采集、运行真实 RPC 或交易。

### P1 Lift（≤ 3 周）
只在 P0 来源/PIT/可卖出条件可信且 Owner 明确签 `继续` 时进入。扩大到 ≥150 个同母体样本，**扩大前**冻结一条规则和固定研究金额、可执行买卖与退出定义；和同母体时间匹配的随机 top-k 对照，按可兑现费后净收益进行分时段 bootstrap。未经留出样本验证与 G5 独立其他 AI 审核，不得声称有投资优势。Alpha 不能改任一入口或替代主要研究对象。

### P2 Paper → P3 Micro-Live
每段都要用户签字进入。P3 需要用户单独写明金额。

### 阶段审核
代码审核从"每个 patch 一次"改为**每阶段结束一次**，审的是"该阶段的唯一指标是否真实"，不是代码风格。

## 7. 止损（机械，Builder 不得解释）

| 条件 | 动作 |
|---|---|
| 阶段 deadline 到，唯一指标未达门槛 | 该阶段 `FAILED`；来源/PIT/买卖条件未证实写 `INSUFFICIENT_DATA`，已有反证才写 `NO_REJECT`，不得延期。**CI 仅在下一次 push 时检查，无后台调度。** |
| 连续 2 份连续周报唯一指标为 `NOT_MEASURED`（或报告缺失且无法证实） | 下次审查/提交时标 `停止`，等用户；**不是创建自动运行任务** |
| `budget.json` 超限 | CI 红，当周不得再 push 其他内容 |
| Builder 修改了本文件/ADR 止损/budget.json | 回退该提交，视为 Acceptor 7 问第 4 条 YES |
| 出现新的 "Stage NNN" 系列文档 | 同上 |

止损触发后唯一合法的"继续"方式：用户在周报上手写 `转向：<新假设一句话>`，重新开 P0。
