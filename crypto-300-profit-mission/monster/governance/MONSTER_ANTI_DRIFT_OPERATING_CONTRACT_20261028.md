# Monster 反漂移运行合同（2026-10-28）

状态：PROPOSED，待用户签字生效。生效后本文件优先于全部 Stage 文档、ADR-001～006 中与之冲突的流程条款；与 `MISSION_SPEC.md` 的资金/授权边界冲突时，以 `MISSION_SPEC.md` 为准。

## 0. 为什么旧止损线没起作用（事实）

| 现象 | 数据（分支 `research/monster-v4-local-discovery-20261010`，2026-10-10 → 10-28） |
|---|---|
| 活动量 | 2442 commits、342 份 monster 文档、206 个 workflow |
| 盈利问题答案 | `G4 UNKNOWN / G6 NO_GO`，母体 `COHORT_NOT_YET_FORMED` |
| 止损线数量 | ADR-001～006 各自含止损条款，无一次实际触发并终止一条路线 |
| 止损被绕过的方式 | ADR-004 在 NO_GO 之后把 CEX 动量恢复为"产品主线"；ADR-005 预注册另一个 CEX 变体；BSC 源 `SOURCE_BLOCKED` 后继续做观察器工程 |

根因不是规则缺失，而是：**判定止损的人就是被止损的人**；**进度用活动量而不是用唯一问题的答案衡量**；**工程投入先于"鱼塘里有没有鱼"的证据**。

## 1. 唯一问题（UQ）

> 在一个代币**第一次能被普通人用固定金额买入**的时刻，用**当时可见**的数据，能否选出一个子集，其**90 天内按预定规则卖出后的扣费净收益**显著优于同期随机选择？

所有工作必须能用一句话说明它如何推进 UQ 的答案。说不出来的工作不做。

UQ 的答案只允许四种：`YES_WITH_EVIDENCE` / `NO_REJECT` / `INSUFFICIENT_DATA` / `NOT_YET_TESTED`。当前答案：`NOT_YET_TESTED`。

## 2. 角色分离（核心机制）

| 角色 | 承担者 | 权限 |
|---|---|---|
| 建造者 Builder | 主开发对话（GPT） | 写代码、跑实验、提交 Git、提议 |
| 验收者 Acceptor | **另一个独立对话**（Claude 或 Codex，每周固定一次） | 只读仓库和周报，只回答第 5 节的 7 个问题，不写代码 |
| 决策者 Owner | 用户 | 只在周报上签三个字之一：`继续` / `转向` / `停止` |

硬规则：
- Builder **不得**修改本文件、不得新建或修改任何 ADR 的止损条款、不得修改 `budget.json`。这些文件的改动只接受用户本人提交或用户在周报上明确写出的指令。
- Builder 的任何"我认为应该调整目标/止损/预算"只能写进周报的"提议"栏，不得直接执行。
- Acceptor 每周只审一份文件（第 4 节周报），不审代码细节；代码细节审核改为按阶段一次（见第 6 节）。

## 3. 机械预算（CI 强制，不可对话绕过）

文件 `crypto-300-profit-mission/monster/governance/budget.json`，CI 每次 push 检查，超限 CI 红、Builder 必须回退到限内，不得以"下次清理"继续：

```json
{
  "phase": "P0_KILL_TEST",
  "max_new_workflows": 0,
  "max_new_monster_md_per_week": 2,
  "max_commits_per_week": 40,
  "max_new_scripts_per_week": 3,
  "phase_deadline_utc": "2026-11-11T00:00:00Z",
  "paid_source_usd": 0
}
```

为什么用机械数：Builder 擅长把每一次"再多一个脚本"论证成必要。数字不接受论证，只接受用户改 json。

## 4. 周报（唯一进度载体，固定模板，不得增删栏目）

文件：`crypto-300-profit-mission/monster/governance/weekly/YYYY-MM-DD.md`，每周一由 Builder 生成，≤ 60 行。

```
## UQ 当前答案：NOT_YET_TESTED | INSUFFICIENT_DATA | NO_REJECT | YES_WITH_EVIDENCE
## 本周唯一指标（第 5 节定义的那一个数）：<数值或 NOT_MEASURED>，上周：<数值>
## 本周做了什么（≤5 行，每行必须以"为了回答 UQ 的 X 部分"开头）
## 本周没做什么 / 卡在哪（≤3 行，用 BLOCKED_BY_<原因>）
## 预算使用：commits N/40，新脚本 N/3，新文档 N/2，workflow N/0
## 止损检查：<第 7 节每条，逐条写 TRIGGERED / NOT_TRIGGERED>
## 提议（Builder 想改目标/止损/预算的，写这里，不执行）
## 请用户签：继续 / 转向 / 停止
```

用户每周只需读这一份、签一个词。看不懂或 Builder 没按模板写 → 默认签 `停止`，直到补齐。

## 5. 唯一指标与验收 7 问

**每阶段只有一个数字指标**，Acceptor 每周只核这一个数是否真实。

| 阶段 | 唯一指标 | 门槛 |
|---|---|---|
| P0 Kill Test | 手工样本数 N（见第 6 节） | N ≥ 30 且有≥5 个 ≥10× 与≥15 个归零/平庸 |
| P1 Lift | 候选规则 top-k 与同母体随机 top-k 的净收益差（bootstrap 95% 下界） | 下界 > 0 |
| P2 Paper | 前向纸面 30 天，按冻结规则，扣费后净收益 | > 0 且回撤可接受 |
| P3 Micro-Live | 用户授权的极小真实金额，实际成交净收益 | 与 P2 偏差可解释 |

Acceptor 的 7 问（只答 YES/NO/UNKNOWN + 一行证据）：
1. 周报的唯一指标数值能否在仓库里复现？
2. 本周所有工作是否都指向 UQ？列出不指向的。
3. 预算是否超限？
4. 是否有任何"止损被重新解释"的迹象（新 ADR、新 Stage、目标措辞变化）？
5. 是否有任何活动量（commit/测试/审核次数）被当作进度表述？
6. 样本是否仍同时含赢家和失败者（分母未被缩小）？
7. 建议用户签：继续 / 转向 / 停止，一句话理由。

## 6. 阶段顺序：先杀后建

### P0 Kill Test（≤ 2 周，截止 2026-11-11，零代码优先）

目的：不写观察器、不写 batch 传输，先用**最笨的办法**回答"鱼塘里有没有鱼"。

做法：
1. 手工（或≤3 个脚本）从公开可查的来源（DexScreener/GeckoTerminal 历史页面、Binance Alpha 公告、BscScan 合约创建时间）挑 **30 个 2025-07～2026-03 首次可交易的代币**，强制比例：≥5 个事后 ≥10×，≥15 个归零/<2×，其余随机。
2. 对每个，记录**首次可交易后 1 小时内**能看到的 ≤10 个字段（流动性、持币集中度、合约是否开源、创建者历史、首小时成交笔数、是否同时有 Alpha/USD-M 渠道……）。字段必须标注"当时是否真的可见"，不可见写 `NOT_PIT`。
3. 把 30 行表放进 Git。**人眼看**：赢家和失败者在这 10 个字段上有没有肉眼可见的分离。
4. 结论三选一：有分离 → 进 P1；无分离 → `NO_REJECT`，换假设（例如从"链上早期"换到"Alpha 公告后首小时"）再做一次 P0；30 个凑不齐 → `INSUFFICIENT_DATA`，**停止该来源方向**，不做工程补源。

P0 不允许：新 workflow、新观察器、新 RPC 传输层、任何"为了以后可复现"的基础设施。可复现性在 P1 才买。

### P1 Lift（≤ 3 周）
只在 P0 有分离时进入。扩大到 ≥150 个样本，冻结一条规则，bootstrap 对比随机。规则在扩样本**之前**写入 Git（预注册），之后不改。

### P2 Paper → P3 Micro-Live
每段都要用户签字进入。P3 需要用户单独写明金额。

### 阶段审核
代码审核从"每个 patch 一次"改为**每阶段结束一次**，审的是"该阶段的唯一指标是否真实"，不是代码风格。

## 7. 止损（机械，Builder 不得解释）

| 条件 | 动作 |
|---|---|
| 阶段 deadline 到，唯一指标未达门槛 | 该阶段 `FAILED`，Builder 必须在周报写 `NO_REJECT` 或 `INSUFFICIENT_DATA`，不得延期 |
| 连续 2 周唯一指标为 `NOT_MEASURED` | 自动 `停止`，等用户 |
| `budget.json` 超限 | CI 红，当周不得再 push 其他内容 |
| Builder 修改了本文件/ADR 止损/budget.json | 回退该提交，视为 Acceptor 7 问第 4 条 YES |
| 出现新的 "Stage NNN" 系列文档 | 同上 |

止损触发后唯一合法的"继续"方式：用户在周报上手写 `转向：<新假设一句话>`，重新开 P0。

## 8. 与现有资产的关系

- 保留并冻结（不再投入）：官方 Binance ZIP/CHECKSUM 读取、身份核验、PIT 哈希留证、资金账本算法、BSC 观察器（含 `edeeb445` 已审核版本）、G0–G6 门禁定义。
- 归档：全部 `monster_v4_stageN_*` 脚本、一次性 workflow、ADR-004/005 作为历史基线。
- 不复审任何已批准 SHA。

## 9. 用户每周实际要做的事（总计 < 10 分钟）

1. 周一读周报（≤60 行）。
2. 把周报原文贴给 Acceptor 对话，要 7 问答案。
3. 根据 7 问第 7 条签一个词，回贴给 Builder。
4. 如果 Builder 要求改预算/止损：只改 `budget.json` 或在周报上写字，不接受其他形式。
