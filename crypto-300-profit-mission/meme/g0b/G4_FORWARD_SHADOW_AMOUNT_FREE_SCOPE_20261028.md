# Frank G4 前向影子研究：无默认跟单金额、事件因果与净收益证据

**状态：OFFLINE_PROTOCOL_ONLY（2026-10-28）。** 这是基于 PR #117 G0-A 和 PR #235 已完成一次性免费历史研究的后续业务规范，**没有启动新的前向采集、监控、RPC、行情 API、交易、通知、Mac 安装或发布**。原试验的未使用 API 配额不得续用。本文件不能替代单独的采集授权、复核或发布许可。

## 当前判断和业务目标

- 历史试验已得到 36 次免费 GET/全部 HTTP200、固定 12 episode，其中只有 6 episode 拿到五档分钟池价代理；预先登记的信号与对照价格覆盖门槛均失败。正式 MULT 时间的价格窗口只有一例可用。结论 **DATA_NOT_SCORABLE / NEED_MORE_DATA**。
- 未来必须回答的业务问题是：**在我们真正接收到 Frank 信号的时刻，用户是否仍有可实现的正净收益机会？** Frank 自身历史收益、先前 ACC 的价格和事后池子排名不能代替答案。
- **用户未指定投入金额时不使用任何默认值。** 只显示事件事实、来源完整性、延迟、历史行情是否可用以及“可执行评估未进行”。不推导、展示或通知固定规模交易报价、滑点、净利金额或下单建议。
- 用户主动输入交易规模后，才可在另行批准的研究范围内针对该规模查询具体**只读报价**。研究结果仍不具备交易权限，不自动写钱包或发送交易。

## 研究单位及因果时间线

| 字段 | 来源与约束 |
|---|---|
| person_id / mint / episode_id / source_signal_id | 必须绑定归档或经核验的实际 Frank 来源；不允许由旧 Mission Control overlay 生成 |
| source_action_signature / event_time | 原链上签名与 blockTime，秒级 UTC；不能拿页面刷新时间冒充 |
| signal_kind / signal_first_available_at | 冻结 ACC 和正式 MULT **分别保存**；MULT 的时点不得回填到更早的 ACC |
| indexed_first_at | 仅在**原始事件首次成功持久化**时记录；现有 schema 无该字段时写 null |
| browser_first_observed_at | 仅页面已打开且事件之后首次呈现，浏览器本地时间；不能替代入库时间 |
| notification_sent_at / delivered_at | 仅当实际有原授权且有相应系统回执时填写，否则 null；未发送不是 0 延迟 |
| pool_id / route / quote_observed_at | 池选择和每笔报价单独提供实际数据证据，不能用当日池排行或历史 K 线反填路由 |
| user_notional | **null，直到用户为研究显式设定金额**；不从别处拷贝任何预设投资数额 |
| executable_entry / executable_exit | 需要相应金额、时间、路由/深度、有效期及成本的可复核读报价；缺一项则 NOT_ASSESSED |
| raw_receipt_sha256 / source_url / parser_version | 保留可复算的数据来源，禁止编造缺失成交、报价或资金余额 |

**真实跟单等待起点**为 signal_first_available_at（还须单独考虑实际到账与浏览器/通知读取时间），不是更早的第一笔 BUY。延迟 T+30/120/300/900/3600 秒依次评估；若其中某时点不存在可执行报价，则该档结果记录缺失及原因，不许以事后最近成交或未来 K 线强行补值。记录同 episode 相关性，同币跨 episode 不能视作完全独立。

## 输出必须分成三张卡片

1. **Frank 正在做什么：** 钱包实际 BUY/ADD/SELL、原始证据、冻结信号、事件时间、模型仓位与实际链上余额的区别；过期与未覆盖明确标注。
2. **现在是否有可跟研究价值：** 事件到索引/页面/通知各环节延迟是否已测得、信号是否仍在有效时间窗、交易池和市场数据是否有可复核来源、当前交易规模是否用户已输入；缺少金额则**不进行执行资格评估**，不能展示猜测的可执行结果。
3. **历史上跟了会怎样：** 只有存在同一金额和同一延迟档的入/出场可复核报价、手续费、价差、影响和可退出证据，才计算研究用模拟净收益率；只拿到 OHLCV 时必须标成“价格代理，仅供研究”，不显示为净收益或真实盈亏。未出现的真实交易绝不伪造成交。

## 分母、否决条件与最终裁决

- 逐 episode 记录：本该观察数、实际索引数、信号覆盖数、真实及时显示数、经验证有执行报价数、买入可覆盖数、退出可覆盖数，以及各类缺失/失败（RPC、源缺失、池不存在、报价过期、流动性不足、交易失败、用户未设置金额等）。**未知不是零，也不能从分母移除。**
- 独立性：历史 M3 训练/开发用过的窗口不作为 OOS；未来样本方案在采集前锁定。避免只选收益好的 Mint、后知晓的池子和存活至今的代币。
- 风险评价：观察净收益分布、中位数、下分位数、最差样本、极端赢家剔除后的结果、延迟敏感性和市场成本敏感性。只报告可复算区间，不把单笔好案例作为策略盈利证明。
- **否决触发：** 信号在链上事件之后才事后生成、正式 MULT 信号发生在虚拟入场之后、缺交易规模仍输出可执行利润、只引用 OHLCV 却称真实成交、延迟/成交缺失被当成零、同一 episode 多笔成交被虚增独立样本、生产/交易受到影响。
- 裁决分开：只读产品可根据真实 Mac 功能与安全验收成为 PRODUCT_GO；策略只有经过预先锁定的独立前向样本、可执行入/出场证据、成本及敏感性验证后才可能 STRATEGY_GO。现阶段仍 **STRATEGY_NEED_MORE_DATA**。

## 业务交付顺序与授权边界

1. **现在可以做：** 修复 F01 已存在的只读展示/API，不引入默认金额；通过独立定 SHA 审核；读取已打开的 Mac Dashboard 作为旧版本只读基线；准备最小可回滚发布。
2. **需要独立发布许可：** 安装整合后的 Dashboard / F01 / CA 到 Mac，且安装前后都要验证真实页面、余额未确认时的标识、通知兼容性和回滚。
3. **需要独立采集许可：** 新增持久化首次入库时间、持续观察新事件、查询实际报价或调用 RPC；权限必须限制周期、数量、免费额度、数据范围、发送策略，不使用自动交易。
4. **需要用户明确输入具体规模：** 才能进行按规模的可执行报价/盈亏模拟。用户也可以只使用前两张来源与时效卡片，不输入任何金额。

此文件是研究与交付边界，不是新 cron、workflow、监控、交易或采购任务。
