# Frank 模块开发与独立复核强制规则

生效日期：2026-10-15，Asia/Bangkok。此文是 Frank / CA / F01 / F02 / A05 等相关子模块的**正式开发执行规范**；与 `FRANK_CA_MULTI_PERSON_IMPLEMENTATION_TODO_20261013.md`、`FRANK_CA_PR_REVIEW_INTEGRATION_GATE_20261014.md` 联用。不能替代真实测试或授权。

## 1. 一条主线交付，不被低优先级边界拖延

每轮固定主目标和用户价值：Frank 真实钱包观察、来源可验证、候选/当前仓位判断准确、界面可操作，按仓库冻结的阶段顺序推进。先核对 Git 进度和不可变目标，再调查证据→给出方案/小范围 TODO→独立分支开发→专项与全量及相关临时联合测试→**其他 AI 独立复核**→Mac 隔离真实验收→必要修复→得到单独明确授权才允许合并/部署。不要因为理论 P3 无休止停在边界；已经证明的实际 P2 需要修复。

## 2. 强制在需要独立 AI 复核的同一回复中直接附上完整提示词

**用户硬性要求：当开发达到“需其他 AI 审查/复审”的门禁时，开发 AI 必须在它向用户报告该进度的同一回复里直接给出可复制的完整独立审核提示词。不得只说“可让另一个 AI 审核”“审查清单已放 Git/PR”或等用户另行回复“提示词”。**

具体必须同时满足：
1. 给出简要状态：本轮业务范围、明确已做/未做，修复对应的实际缺陷，GitHub PR 链接、**精确 40 字符审核 SHA**、固定比较基线、Draft 与部署门禁。
2. 在 Git 和 PR 评论归档同一份审核清单/提示词，**在用户对话中也直接显示完整可复制提示词**；Git 评论只是审计副本，不是替代品。中文可直接粘贴给 Codex、GPT 系列或另一独立 AI；不要将审核当成本 AI 已独立完成。
3. 提示词覆盖：仓库及固定 PR/SHA/base、审查限定 diff、与现有 TODO/开发规范和上一轮独立审核报告的关系；要求复核来源门禁和用户最主要功能、真实 HTTP/浏览器及时间依赖场景；独立测试命令和初始 CI 证据；前后远端 SHA 核对；缺陷分级、实测复现、报告和明确 APPROVE/REQUEST_CHANGES；不得擅自改代码或合并生产。
4. 新一轮 REQUEST_CHANGES 必须保留旧 SHA、原复现实测、失败 CI/证据；**另开最小修复子 PR**，补最小针对性真实回归，冻结新的 40 字符 HEAD 后重新执行适用专项/全量/临时联合，**再立即随结果附上该新 SHA 的完整复审提示词**。审查已批准上游模块只复核关联接口，不无故扩展。
5. 如果 CI 还没全部绿灯，先准确报告 `CI_RUNNING` 或失败结果，不能提前给出声称可批准的固定审核结论；代码完成和独立审核结论、真实 Mac 浏览器验收以及生产发布资格必须分开表述。

## 3. 实际源码/时间时效安全

- 完整来源和最新实际采集尝试分别核查；新 partial/失败来源不能使旧正余额复活。时效控制覆盖**页面保持打开跨 TTL**，不能只在 API 接入、首次载入或手动刷新时检查。到期自动本地遮罩数量、账户数量、有效状态与统计；搜索筛选、页签重新可见时必须重新检验。**不允许因此引入自动链上 RPC 或延长 TTL**。
- 真实 32 Mint 冻结名录和原始原文 SHA 审核由上游完成，2026-10-14 归档 9 非零/23 零不表示现在仍持有，也不证明 SELL、PnL。 `SOURCE_UNAVAILABLE` 不表示余额为零。
- 研究侧 Sidecar 必须单独明确用户授权，不重导入已经成功创建的 SQLite。Mac、Git、浏览器的证据来源单列；不可将 GitHub Actions 绿色冒充 Mac 业务验收。
- 只读研究端与生产 Dashboard、Frank V1、Gmail、交易、LaunchAgent 隔离。保留 `NO_MERGE / NO_DEPLOY / NO_TRADES / NO_GMAIL / NO_PRODUCTION_SQLITE_WRITE / NO_NEW_AUTOMATION`，未经明确批准不解除。

## 5. 2026-10-16 正式用户界面 F02 去重与审计字段禁止展示

- 用户于 2026-10-16 Mac **真实 Safari 合成数据**截图审阅确认：F02 `/research/positions` 作为独立开发验收/内部研究页面可以保留，但**不允许成为正式产品第三个重复业务页面**；正式产品的用户导航仍以「Frank 信号」和「CA 链上研究」为主。完整 32 Mint/ATA 核验属于后端 A05/F02 服务能力，其对用户有用的真实持仓/来源有效性数据应在原 Frank 信号/观察/仓位区域消费，而非让用户在独立 F02 页再做一次筛选。
- **正式 UI 强制禁显字段**：`来源 Slot 区间` 和 `来源 SHA-256`（及相关复制按钮/技术来源摘要/折叠详情）。研发 F02 专用验收页面可见，但正式普通用户的页面、列表、弹层/折叠详情/DOM 组件中不可显示；不会因此从原始链上证据、后端来源验证、manifest 或审计日志中删除 Slot 与 SHA，也不得隐藏/跳过校验。不得将开发 QA 标签或 synthetic BUY/金额引入正式页面。
- 正式持仓卡片只展示可核实的业务层信息：明确的人物-钱包-Mint 绑定，实际余额（若完整双程序且时间未过期），最后有效观察时间、当前来源状态/缺失原因；模型仓位与链上钱包仓位分列，零余额不是已卖出，来源未知不是 0。多人物/多钱包仍保持只读研究权限隔离，不被本次 UI 收口修改生产策略。
- 任何后续正式 UI PR 必须带**实际 DOM**负面验收：不存在 Slot/SHA 文案和复制操作、不出现 F02 第三业务 Tab、合成 SELL/NO_BUY 不进入当前可跟、来源 TTL 失效后旧余额不复活；独立其他 AI review 固定 SHA 与 Mac 正式浏览器实测。原已通过 F02 内部研究来源页与后端可继续测试，不回溯变更已审核 PR #73 的 Git 组装源码。此条为用户产品要求，**不是**当前真实 Mac Safari 浏览器所有条目验收通过。
