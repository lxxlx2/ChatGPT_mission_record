## Real gap closed by this code-only prerequisite

The D1 Mac protected entry `_inspect_fixed_registry` formerly checked prospective fixed registry path equality, symlinks and root private mode, but **did not inspect ownership of actual OS-account home and every directory component**, nor open the final inode with `O_DIRECTORY|O_NOFOLLOW` for read-only fstat identity validation. Existing `f0_l2_d1_grant.PRIVATE_FIXED_REGISTRY` is computed from `Path.home()`, which can be affected by `HOME`; the protected code would fail closed when that differs from actual OS passwd home, but no separately reusable preflight reported exactly why.

New `f0_l2_d2_os_registry_readonly.py` obtains the OS account home from `pwd.getpwuid(os.getuid()).pw_dir` regardless of `HOME`, enforces absolute account-owned home, *exact* pre-existing constant `PRIVATE_FIXED_REGISTRY` matching account home + `Library/Application Support/MissionEvidence/f0-grant-registry`; never creates anything. It checks each expected component with `lstat` for non-symlink directory and account UID ownership, requires owner-private `MissionEvidence` and registry, and finally opens only the registry **read-only** as an `O_DIRECTORY|O_NOFOLLOW` fd. It fstats the opened inode and checks its identity against the path at inspection time. Missing any directory reports NOT READY with zero writes; swapped, symlinked or permissive component rejects.

The original `f0_l2_d1_protected_mac_entry._inspect_fixed_registry` now delegates to this **single** stronger inspection instead of adding an alternate registry. Existing output fields are preserved with additional `os_account_bound`, `production_authorized=False` and a read-only inspection note. `registry_opened` may now indicate **a directory opened read-only**; it NEVER means a grant marker was opened or consumed. No change to `OfflineGrantRegistry.consume`, `FixedLocalGrantRegistry`, OS process supervisor, source transport, pooled RID/RAW writers, new signer roots, production release constants or any send entry. Importing the module cannot create a grant.

The read-only result is a point-in-time directory-layout check, NOT race-free proof for a future executor. An authorized later run would need to bind and retain the exact verified OS directory fd and perform atomic O_EXCL marker consumption+fsync under that fd, while holding independently verified real user/reviewer D2 and D3 signing approval. This child **does not implement any such marker or enrollment** and does not claim filesystem correctness against hostile admin/OS or arbitrary Python monkeypatching.

## Root-cause correction after second identical CI failure

[Second CI 40271757595](https://github.com/lxxlx2/ChatGPT_mission_record/actions/runs/40271757595) reproduced **578 tests, 17 FAIL / 17 ERROR** even after updating the synthetic account fixtures. Source-level inspection then identified the actual universal rejection: `type(PRIVATE_FIXED_REGISTRY) is not Path` is **always true** for a normal `Path(...)` instance, since POSIX/macOS constructs `PosixPath`. Fixed in commit `f1c974f5951206df066d0d1a0baf415ff1eb068b` to `not isinstance(PRIVATE_FIXED_REGISTRY, Path)`; exact path equality, OS UID/home validation, private ownership and fd/no-follow checks remain strict. This is the substantive cause and the old log is retained. Fresh exact-SHA CI is needed. Neither the first nor second failed SHA is approved.
