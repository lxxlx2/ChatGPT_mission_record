## 已观察事实与设计结论

从 [PR #151](https://github.com/lxxlx2/ChatGPT_mission_record/pull/151) 用户 Mac 的**私有离线回放记录**：首次只读试验收到 60/60 未来完整块、共 5940 交易、冻结 PRIMARY from 命中 0、Router-to 地址候选 40；header 时间跨度 **26 s**，本地首末块接收跨度 **58.979 s**，差 **32.979 s**。完整区块请求/解析时长中位数 **766.309 ms**。`receipt − header timestamp` 从 **2.01 s** 变为 **34.99 s**，是受秒级头时间戳、Mac 时钟和节点滞后共同影响的**滞后代理**，不是独立的链头滞后或全球首次广播时差。所有原始 HTTP 字节只在用户本机，**本 PR 没有再读取或重新验证这些私有数据**。

- 该 59 个区块间隔的平均头时间差约 **440.678 ms/高度**；真实已观察的本机接收节奏约 **999.644 ms/高度**。
- 仅去掉固定 1 秒节拍、以 **766.309 ms/请求的既有中位数**作为理想化串行处理速度，59 个间隔的**假设差距**仍约 **19.212 s**。这不是实际新实验数据，更不是未来网络速度保证；它说明单纯改定时器不等于能持续追头。
- 所以应在**同一来源、明确计费请求分母**内增加链头采样，并按已确认的高度取块；定期衡量已确认 head 与处理进度之差，区分“请求高度覆盖”与“是否跟得上最新 head”。若串行吞吐仍慢，应先考虑降低响应时间、受控并发或免费低延迟来源的可靠性和独立审核，而不是直接把观察窗口从 1 分钟延长到 24 小时。

## 新增离线调度器的实际作用

`f0_l1_adaptive_head_plan.py` **没有** `urllib`、socket、WS、RPC 调用器、许可、终端运行入口或自动循环；没有更改 [PR #149](https://github.com/lxxlx2/ChatGPT_mission_record/pull/149) 的真实运行脚本。仅提供纯函数：

1. `init_plan()`：接收一个**外部已验证并记账**的初始 BSC head 高度，设置块读取/后续 head 轮询**各自独立的预算**、两次请求最短间隔和 head 刷新阈值。初始 `eth_chainId` 和 `eth_blockNumber` 的真实调用不在此纯调度器模拟预算中，未来 live 驱动必须额外纳入其**单一实际总预算**。
2. `next_action(state, now_ms=...)`：输出 `READ_HEAD` / `READ_BLOCK` / `WAIT` / `STOP` 的决定，不进行网络。绝不选择高于**最近一次外部验证 head** 的区块高度；定期请求新的 head；调用次数/间隔不足时停止或等待，不凭本地时钟臆测 head 新高度，也不 silently skip。
3. `apply_head_result()`：记录一次已发生的**虚拟/外部已审计** head 尝试；新 head 低于旧值或 HEAD 来源失败即停止，没有在本模块中暗藏重试。
4. `apply_block_result()`：记录一次确切高度的读取结果，显式累计成功、失败与缺块；缺块不作隐形重试，后续只前进至下一高度。
5. `throughput_scenarios()`：只对已经归档的跨度、中位数做**算术假设**，明确标记 `scenario_only=true`；输出“去掉固定等待仍追不上”的判断，但**不**输出冒充实测的 head lag 或新 RPC 数据。

该纯调度器 **不证明** 实时性能，也不负责发送前 fsync；将来要连到真实 BSC HTTP 时必须复用已审核的独立 Journal（含 HEAD 与 FULL_BLOCK 每次尝试的落盘预记账），严格保证读取头失败、TTL/nonce/budget/响应原始字节等任何限制都不会被调度器绕开。**不得直接把这个模块接进线上 runner 而跳过代码与许可审核。**

## 本轮测试

新增 `tests/test_f0_l1_adaptive_head_plan.py` **10 项**假 head/假块测试，重点覆盖：

- 未确认新高度前不请求未来块，HEAD 采样后只读取已确认高度，达到刷新阈值再检查 head；
- head 轮询预算、块读取预算独立计费，失败 head 停止，head 高度回退停止；
- 块失败占用预算并留下确切缺失高度，无隐形重试；
- monotonic/最短请求间隔阻断；
- 使用 PR151 的 **26s、58.979s、766.309ms** 观察摘要构建情景，证实仅取消固定等待，乐观串行处理假设仍产生约 19.212s 的累计速度差；另一个虚构较快来源情景必须写 `POSSIBLY...NOT_YET_PROVEN` 而非 Go。
