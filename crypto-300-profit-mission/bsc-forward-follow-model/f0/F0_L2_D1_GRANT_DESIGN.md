# D1 授权身份与全局一次性登记（仅离线、没有真实信任根）

- 两个角色 user 和 reviewer 使用独立的 Ed25519 公钥。通过固定版本 `cryptography==46.0.4` 的 Ed25519 实现验证离线签名（Mac 系统 LibreSSL 不支持此算法），签名绑定原始 permit 字节哈希、审核代码 SHA 和角色；同一密钥身份不能同时担任两个角色。测试中用只存在于内存、临时生成的**测试私钥**验证正确签名、交换签名、篡改签名及变更许可负例。**不会将任何私钥、签名或真实许可提交到 Git。**
- 生产信任根映射故意为空，`validate_live_trust_roots_not_enrolled()` 必然拒绝。D2 必须通过单独、可审核的用户信任根登记与实际许可审核机制，不能以“当前测试签名可验”作为真实授权。若需要修改生产信任根，必须是以后用户明确授权的单独代码/许可审查事件。D1 不具备网络入口。
- 一次性登记对象 `OfflineGrantRegistry` 使用固定 grant ID（与输出目录无关）计算标记名。0700 注册目录中原子 O_EXCL/O_NOFOLLOW 创建 0600消耗记录，fsync文件再fsync目录；即便写盘失败也不删除占用标记，不自动重新使用。两个进程争同一grant只有一个成功。**这个对象仅是离线可注入根目录的测试原语，不是生产入口**：D2真实入口必须将注册目录绑定到固定私有路径，禁止从 permit 换路径。
- 适用边界：注册文件若被拥有本机完全读写权限的攻击者物理删除，单机登记无法提供跨机器、跨操作系统恢复的全局永久唯一性；需要独立不可重放的外部批准记录/不可变信任锚，这一限制必须在D2证明已解决。D1不允许据此放行。
- 未提供任何 `--execute-live`、`post`、网络客户端、permit生成脚本或旧许可重用。所有功能只用于离线回归。F0_NOT_PASSED / PRODUCTION_NO_GO。

**Mac/Linux 离线环境约束：**CI 与 Mac 审核必须从同一个 `requirements-d1-offline.txt` 安装精确版本。缺包报 `D1_ED25519_BACKEND_UNAVAILABLE`，错误版本报 `D1_ED25519_BACKEND_VERSION_MISMATCH`，绝不静默 SKIP、改用系统 LibreSSL 或跳过验签。D1 pin 的仅为包版本，真实 D2 仍需逐文件/wheel 字节与生产信任根审核；Mac Python 测试必须用新隔离 venv。
