## New module: f0_l2_d2b_signed_execution_offline.py

- This module adds a **signing-message constructor** with a separate domain `bsc-f0-d2b-one-shot-operator-signature-TEST-ONLY-v1`. The canonical signed bytes include: entire raw D3 intent SHA256, entire raw D2 permit SHA256, reviewed 40-character code SHA and actual 64-character tracked source-manifest SHA256. This binds the source/deployment identity and all D3 fields without unsafe JSON recanonicalization. Swapping any intent field, source, permit or commit breaks the signature. Message helper strictly rejects malformed SHA shapes.
- `verify_three_role_test_proofs_offline` composes the **already reviewed** `bind_real_https_candidate_offline` structural budget/endpoint/UTC validation and D1 `validate_approvals_offline` Ed25519 user and reviewer **over D2 permit raw digest**. It then verifies an independently signed D3 operator proof using the **same pinned `cryptography==46.0.4` backend**. All **three public key byte fingerprints and key labels must differ**; a copied signer key under another label, replay of D2 signature as D3 or changed signing-domain is forbidden. Explicit three-role data shape must match exactly.
- Public roots are **caller-injected test fixtures**, not an enrolled trust anchor. The returned immutable-in-intent diagnostic is a plain Python dict that carries only digest and **`OFFLINE_EPHEMERAL_TEST_ROOTS_ONLY`** status, explicit `production_trust_roots_enrolled=False`, `real_user_authorization_proven=False`, `actual_rpc_requests=0`, `PRODUCTION_NO_GO`. **Never** pass it into a live sender. The module defines `PRODUCTION_D2_D3_TRUST_ROOTS = {}` and `send_live()` unconditionally raises `D2B_LIVE_SENDER_NOT_AUTHORIZED`. No signing APIs, issuer, file writes, credentials or network implementation were added to runtime.
- Existing D1 `f0_l2_d1_grant.PINNED_LIVE_TRUST_ROOTS` remains empty. No activation changes to the single `GlobalStartGate`, `run_fake_concurrent`, `request_physical_source_admission`, `f0_l2_d1_concrete_https`, Mac protected entry or OS one-use grant. The new module **cannot construct a transport** or consume a registry; signature verification only proves that *test-generated* keys match *test-supplied* public keys.
