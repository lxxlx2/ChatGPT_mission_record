# 449钱包地址分析：UPTOBER九钱包同步资金簇与亏损候选（2026-10-19）

研究范围为独立 Mission PR #97 地址分析模块。原始449只包括该簇的 #213 与 #429，其他7地址仅作链上关联上下文，**不得自行当作449名单内的7个新钱包，更不得当作七份独立盈利统计**。

## 确认事实（已调用真实 BSC 链读取）

1. **九个不同钱包在同一个区块 `0x77431c3` 各自原生 BNB 余额恰好增加 `0.125000000000000000 BNB`**；对#213和#429两者签名nonce无变化，说明这两笔不是本人的签名付款，现有Alchemy免费层无法确认内部来源。
2. **九个钱包均本人签名调用同一个 Router `0x1de460f363af910f51726def188f9004276bf4bc` 买入同CA UPTOBER `0xd1d21633b34312a3f490ef2d111bfe0342b47777`，都在同一个区块 `0x7745165` 本人签名卖出。** 对每个钱包，入账一条ERC20，卖出同一交易分成两条Transfer事件，**原始代币数量入=出**，当前样本未发现exact CA另有分页。
3. **九个钱包均在区块 `0x7745218` 发出普通 BNB 付款，转入同一地址 `0xc415f5c509dece39b1ab27ba5697053a5ffaae3a`；该块getAssetTransfers的9条来账全部取得，分页耗尽。** 转款后九个钱包各自原生余额**完全相同，为 `0.000197480000000000 BNB`**。
4. 九个钱包 UPTOBER 买卖**执行区块**的BNB余额变化各自负向，合计 **-0.003381868131152993 BNB**。注意这不是9个地址全资产的已实现净亏损；它只核对买卖所在区块，不包含所有币、其它签名动作和 Router 内部 native 交易Trace。九账户收到的0.125 BNB资金和归集资金也不是PnL：原始期初余额及 O2/O5 的额外签名交易可造成资金变化，单独把集体扫出资金与1.125 BNB注资相减会错算盈利。

## 对盈利统计的实际意义

- **高度疑似同一个自动化流程/批量执行策略**，可归入 `HIGH_CONFIDENCE_SYNCHRONIZED_FLOW_CLUSTER`；这仅是交易行为和资金聚合事实，**不认定真实控制人/身份证明**。
- #213/#429（原始名单内）应在盈利评估中分别保留 wallet 级账本和 cluster 级去相关视图；除非证明同主，不能在法律意义上当作单一钱包；但不能直接当成两个独立获利样本来拉高策略胜率。
- **九个UPTOBER买卖区块余额变动全部负向**，因此既有“聪明钱”列表成员并非意味着每次交易都挣钱。当前确认的是负向资金变化，不是去掉所有其它资金流/费用的审计利润。
- 簇中两个额外钱包的BSC签名增量为6，另7个为4（包括原始#213/#429），这印证跨窗口资金活动并不完全一致，不能套用统一完整盈亏。
- BSC免费Alchemy不提供 `debug_traceTransaction`、`trace_transaction`，该网络内部分类查询不支持；Blockscout插件不支持chain ID 56。**既不建议付费，也不建议因此卡住其它钱包的盈利审计**。
