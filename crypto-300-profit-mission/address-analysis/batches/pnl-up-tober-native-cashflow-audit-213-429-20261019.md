## 新关联：同一高度收到精确同额原生 BNB，扫到同一地址且剩余完全相同

1. 两钱包在BSC区块 **`0x77431c3`** 的原生BNB余额均较区块 **`0x77431c2`** 增加**精确0.125000000000000000 BNB**，**本人签名nonce没有变化**（#213 14353→14353；#429 6913→6913）。对于两者，在冻结历史区间 `getAssetTransfers(toAddress,external)` 均没有原生BNB普通外部来账事件。说明存在非普通外部事件的本币余额入账，**目前不能独立查到真实内部调用/来源地址**。
2. 两钱包均在BSC区块 **`0x7745165`** 完成同CA UPTOBER卖出；各自是不同钱包的签名不同交易，不能单凭同区块断定同主。
3. 两钱包又在区块 **`0x7745218`** 分别签名直接转账至**同一地址** `0xc415f5c509dece39b1ab27ba5697053a5ffaae3a`，分别转出 **0.124340737124639661 BNB** 和 **0.124634827445104611 BNB**。两笔付款Gas均精确 `21000 × 120000000 wei = 2520000000000 wei`，付款后以及冻结终点**都恰好保留 0.000197480000000000 BNB**。该收款地址在转账块 `eth_getCode=0x`（无部署代码）。
4. 额外一笔仿冒BNB外观的ERC20转账事件 `0x7426ff990e98d6bf401ce7aadf398b4cbbe37aee91f835e16ab93833283e54b5`，同笔交易的事件中分别写入两个钱包为 `from`。**ERC20 事件中的 from 不能当作交易本人签名**；该笔没有出现在上述任一钱包4笔本人nonce序列中，禁止记为钱包卖单或“两个钱包共同签名”。

## 为什么还未批准整体净盈利

在已连接的 Alchemy 免费BSC实例尝试读取 `debug_traceTransaction` 和 `trace_transaction`，均实际返回需升级付费的错误；`getAssetTransfers(category=internal)` 对BSC明确不支持。另试第三方 Blockscout连接器，结果其索引不支持BNB Chain（chain ID 56）。**不是主观选择不查，而是当前可访问来源不足。** 0.125 BNB的入账不能定位父交易/内部来源，买卖内部native回款也不能逐交易核验，因此必须把更高级别的盈利声明保留为未确认。
