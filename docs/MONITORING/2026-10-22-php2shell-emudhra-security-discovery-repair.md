## What actually happened

**PHP2Shell**: 2026-10-21 PHP upstream emergency release for CVE-2026-109618 and CVE-2026-109619, both CVSS v4 9.2, potentially unauthenticated web-server RCE. Supported releases 8.2.35, 8.3.36, 8.4.27, 8.5.12 available. PHP mod_php is particularly exposed; PHP-FPM, php-cgi, FrankenPHP and LiteSpeed must check vendor fixes. Cloudflare reports attack traffic attempts but this is not proof of universal successful attacks. Source: https://www.php.net/archive/2026.php and https://www.enisa.europa.eu/news/joint-statement-on-critical-php-vulnerabilities and https://blog.cloudflare.com/php-vulnerabilities-waf-protection . CZ X signal: https://x.com/cz_binance/status/2113029289155178716 . An influencer's mention is supplemental, not proof of technical facts.

**eMudhra**: 2026-10-17 report / 2026-10-20 public disclosure / 2026-10-21 CERT-In advisory. Eight intermediate certificate signing private keys were very low integers 4,56,66,115,155,156,230,237, instead of secure 384-bit secrets. Potential impersonation of TLS websites when attack controls traffic and victim client still trusts the affected key; NOT a flaw in the Chrome browser engine. Chrome, Firefox, Apple, Microsoft distributed emergency blocks and eMudhra revocations. Unpatched custom TLS clients and OS trust stores may still need repair. Chrome reports no CT-logged TLS leaf certificates issued by the affected intermediates before its blocks; this is not proof of malicious widespread successful use. Sources: https://blog.mozilla.org/security/2026/10/20/protecting-firefox-users-following-the-compromise-of-emudhra-intermediate-certificates/ ; https://blog.google/security/protecting-chrome-and-android-users-from-compromised-emudhra-intermediate-ca-certificates/ ; https://www.cert-in.org.in/s2cMainServlet?CACODE=CICA-2026-3649&pageid=PUBADV01 .
