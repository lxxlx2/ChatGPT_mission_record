## 1. 最终目标，用用户能理解的话说

1. **保留原来的 Frank 买币行为提醒**：Frank 出现 ACCUMULATION（持续建仓）→ 原有本地提醒，MULTIPLE（多次强加仓）→ 原有本地 + Gmail。保持原始信号的触发、发送方式、证据与去重不变；新代码不能删除、改名、屏蔽或重发已有信号，也不能抢走它的 outbox。
2. **新增金额无关的智能分析**：某代币为什么值得关注，Frank 的活跃买卖、次数、最近一次买入/卖出及钱包持仓状态，市场价格相对 Frank 已核实的买入成本/参考价变化，已有证据能支持的风险提示。**不需要用户先决定买多少**。
3. **额外风险提醒**：例如 Frank 已减仓/卖出、模式失效、价格相对来源参考点显著走高、行情数据过期/不完整、链上成本币种不明等。只在出现**新的可验证重要变化**时提示，不重复发送旧 V1 买入事件。
4. **保留决策权**：提醒用于进一步调查，并非买入指令，不默认 `$30` 或任何交易金额，不自动询价某个假定订单规模，不提交交易、不签名、不设置仓位或止损。用户以后主动提供金额时才能单独评估该金额下的滑点、路由、实际可成交性；信息提醒不依赖该步骤。

**禁用的错误替代方案**：直接启动现有 MC「无金额 WAIT/NOT_ASSESSED」通知并宣称已经实现智能买入分析；把 UNKNOWN/NOT_ASSESSED 解释成没有流动性、完全不能买或可执行 BUY/SMALL_BUY；用截图/历史 D2 数据伪装成实时价格或当前仓位。

## 3. 新提醒的最小信息结构（第一版只要能用，不追求指标数量）

每条“分析”至少写明：

- **发生了什么**：币名/CA/链、Frank 行为（买/卖/继续买/退出）、何时、多少次、已核实交易量/成本及其币种、可验证签名/来源链接；不认识的金额单位原样注明，不补算假数字。
- **当前相对位置**：若**同口径**价格和观察时间都可靠，显示“当前参考价格相对 Frank 已验证买入参考价变化 X%”及来源时间。否则显示`PRICE_UNAVAILABLE/STALE/INCOMPARABLE`，不构造涨跌百分比，更不把相对价格变化说成用户 PnL。
- **风险与失效条件**：至少标出 Frank 最近是否卖出/减仓、买入是否仍在有效观察窗口、数据是否过期、价格是否明显追高；价格或池子风险必须有可核实输入才给出等级。流动性、honeypot、滑点需要特定证据时才作结论，**未检查=未核实**。
- **下一步可执行动作**：复制 CA、打开有来源的链上交易、查看 Dashboard/价格来源、继续观察；无需金额。可选“输入自己的金额查看报价”只能由用户主动触发，不生成订单。
- **结论语义清楚**：`值得关注/谨慎观察/风险升高/信息不足` 只是研究标签；`NOT_ASSESSED` 仅指**该用户金额下的执行评估未做**，绝非“不能交易”。

示例格式（仅说明目标，不是实时事实或推荐）：

> Frank 在过去 60 分钟再次买入 [CA]，当前为「多次买入」，链上证据 [签名]。参考价相对最近一次已核实买入价上涨约 X%（价格源：...，采集时间：...）；若该价格不可核实则只显示「价格未验证」。风险：Frank 最近有无卖出、价格追高、数据新鲜度。建议：关注并自行确认，**不包含购买金额、买入指令或已验证成交能力**。

## 4. 提醒触发和防打扰：不重复旧系统

- **原 V1 原样运行**：ACCUMULATION 本地、MULTIPLE 本地 + Gmail、历史记录去重规则不变。
- **新智能提醒**：只有在有增量的可验证事实后触发（例如一个新的 Frank 增持事件引入了新的风险说明、Frank 卖出使此前观点失效、可靠价格发生风险状态跃迁）；与同一 `source_signal_id` 的原始 V1 通知要区分 **RAW_SIGNAL 与 INTELLIGENCE_UPDATE**。
- 研究信息允许先落 Dashboard/审计，不等于启用第二路本地/Gmail。**新的智能提醒通知范围和发送通道须随正式策略由用户单独批准**，尤其不要在 MULTIPLE 时无新增内容却重复发 Gmail。
- 一次风险变化只发必要更新；`source_signal_id + mint + evidence_version + risk_state` 建议作为确定性幂等身份，具体键在设计阶段用现有持久字段验收后再锁定，避免破坏现有通知去重。
- 新消息不得重发历史待处理 outbox；过期/缺来源时间时只留 Dashboard 与审计，无实时通知。
