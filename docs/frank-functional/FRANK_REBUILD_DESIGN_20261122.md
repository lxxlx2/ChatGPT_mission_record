# Frank 重做技术方案：Meme 买入监控与中文 CA 查询

方案冻结于 2026-11-22（Asia/Bangkok）。基础、历史反例和逐项验收编号见[需求反查](FRANK_REBUILD_REQUIREMENTS_20261122.md)。实现、回归和上线缺口见[联动回归记录](FRANK_REBUILD_VALIDATION_20261125.md)。

## 1. 一个研究台，两种使用场景

以 2026-11-26 Chrome 预览的用户反馈为准。页面使用统一名称「Meme 研究台」，切换入口叫「买入记录」和「CA 查询」。固定页名随功能切换保持一致。旧审计用于排查投递、策略、链上流水和历史记录，保留已有内部地址及证据，移出主导航。CA 历史报告是用户工具，收在查询页的「历史报告」中。两者用途不同。

| 场景 | 默认展示 | 用户点开后 |
| --- | --- | --- |
| 买入记录 | 代币、买入时间、美元花费、买入价（USD/枚），按链上时间从新到旧。 | 查看原交易、复制 CA、进入该 CA 的查询。同一功能提供时间和 CA 筛选。 |
| CA 查询 | 精确 CA、代币、市场摘要、指定池的 K 线和近期成交、简体中文叙事、单行 CA 认领及有数值依据的重点风险。 | 切换池和周期，以及进一步查看持有人、开盘买家、指定钱包、来源、历史报告和完整尽调。 |

买入页移除「仅展示本地已索引且证据齐全的买入」及模型、报价、路由和技术水位说明。按同一美元口径展示，统一保留两位小数；低于一美分的非零美元单价用带两位尾数小数的科学计数表示。对价、数量与源精度仍保留用于计算。美元价格必须对应实际成交时点和资产。优先使用可复核的同笔美元花费或成交证据，并可用同一时点的支付币美元证据折算原币花费。买入价是美元花费除以实际收到数量得到的成交单价。缺少所需证据的格子用「—」。当下报价、稳定币面值、图表近似价和不同时点的价格不用于填补。买入页读取已存事实，不触发新的链上扫描。

界面用简体中文。正文只放有内容的事实和必要的操作结果。叙事栏保留相关原帖、项目网页和能复核的中文叙事。只有找到作者、发布时间、引用或互动时才列出对应项。单条认领状态表示是否找到针对该 CA 的认领；点来源可自行核对。内部来源常量、读取时间和覆盖细节保留在原始数据与明细。删除查询教程、重复的认领状态、没有作者或主题的占位解释，以及访问墙、全网检索范围等运维说明。

### 视觉系统与走查

参照 [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) 先审视视觉系统，再编码并在 Chrome 验收。

- 色彩用盘口的冷色对比建立阅读顺序。画布 `#EEF2F4`，内容面 `#FFFFFF`，深青导航 `#12363C`，正文 `#16272B`，次级正文 `#52666B`，可操作控件 `#087B73`。唯一重点色用于选择和操作，买卖颜色配方向文字。
- 字体优先系统苹方和同类简体中文无衬线，字号用 13、15、18、22 px。金额等宽数字右对齐，中文与代币名左对齐。地址允许复制，以可折行或截短的视图显示，值保留完整。
- 买入记录参考交易账本。紧凑筛选行之下是一张可扫读列表，桌面按交易字段对齐，窄屏在同一笔买入内换行。CA 查询参考盘口信息顺序。搜索和行情数字靠前，图表使用主要阅读宽度，叙事与风险沿纵向排列。历史和完整证据折叠。
- 草案走查去掉巨型页头、成排等尺寸卡片、技术状态条和渐变。保留统一导航、实际行情图和账本数字作为页面辨识点。每段文案只承担一个功能。加载、失败、空结果靠近操作，键盘焦点明显，使用键盘能完成切换、筛选、搜索、读取历史和切池。减少动态偏好下去除过渡。
- Chrome 验收包含桌面、窄屏、键盘和焦点、高对比文本、买入金额及小额单价、叙事缺字段、认领状态，以及切池和前后页面切换。预览只用一条简短的演示标识，两个主入口都有可检查的内容。

## 2. Scanner 买入准入与邮件

### 数据流

`现有 Solana 私有 RPC → 原始交易及游标 → 钱包经济行为 → Solana Meme 身份 → 买入事实 → 列表 / 既有通知判定`

| 判定 | 输入和输出 | 关键反例 |
| --- | --- | --- |
| 采集绑定 | 输入启用的 Frank 钱包、已存游标。解析已确认交易及钱包可归属的账户变化，形成可追溯的原件和候选经济腿。记录槽位、链上时间、采集/入库时间和缺口。 | 外部付款人、聚合器、委托、多腿、ATA 建立和关闭。分页重复可去重；遇未取回原件记录待补，恢复不会跳过。 |
| 主动买入 | 交易成功、可核的 Frank 授权或受益资产归属、目标币净取得、可核购买对价。路由内部腿归并为实际买入；原币对价、手续费、租金各自保留。 | 只有签名、只有净余额、空投、被动转入、转账、归集、卖出、失败和 Relay 付款均不得形成买入。复杂交易有多个独立买入时各记实际经济腿。 |
| Meme 资格 | 精确 Solana Mint + 资产身份记录。沿用已有链上发行/项目与可核来源，保留分类依据。验证不足时仅入待核和私有审计。明确排除记录优先于同名、发行平台或第三方标签。 | BP、非 Meme、同名异币、稳定币/报价资产、仅因使用 Solana USDC 付款或走某交易平台的外链资产。如有明确非 Meme 证据，链上确实买入也不进入 Meme 买入页。 |
| 事实与通知 | 买入事实按人物、钱包、签名、Mint 与实际经济腿绑定。合格事实交给通知前再校验 Mint 与事件身份。保持原策略、事件与 outbox 去重关系。通知内容仅呈现买入事实及可点链接。 | 旧台账读取、CA 查询、重启、重放、修复历史误报都不会追发旧邮件。未知结果先核实际回执。 |

用现有事实/流水和通知存储，新增用户视图优先从事实筛选，避免每次打开重算 Scanner 历史或新增常驻任务。冻结的 ACC/MULT/HFT 与现有渠道规则继续保留审计身份；买入列表可逐笔展示已确认事实。“有买入”与“符合既有邮件规则”分别验收。真实 BP 邮件根因仅在获得相应发件台账、原交易和运行策略时判定。

资产资格按「链＋完整 Mint」保存判定、来源、观测时间和依据。已核实的本地资格记录优先复用；未见过的 Mint 查已有来源，项目自述、发行平台和名称可作为线索。证据冲突或不足保留待核，后续在已有采集流程中补证并统计尚未纳入的范围。资格从待核转为已证实时可补入历史买入列表，通知继续遵守原身份与时效规则。

**对账方法。** 用独立链上参考快照及同时间窗 Scanner 备份逐签名核对。注明参考来源覆盖与区间，不以 Scanner 自己产出的列表作正确答案。至少分别统计应入/实入、应拦/实拦、仍待证、追赶后遗漏和重复、每段延迟。把 BP 负例与确实买入的 Meme 正例走到准备入队的完整判断路径。真实渠道送达与沙箱不发送的恢复测试分列。

## 3. 对照 GMGN 的查询功能

[GMGN 中文代币详情](https://docs.gmgn.ai/cn/dai-bi-xiang-qing-yekxian-duo-tu-biao-jiao-yi-huo-dong-jiao-yi-xi-tong)用于核对查询项目与阅读顺序，[开盘/前 70/持仓口径](https://docs.gmgn.ai/index/insider-traders-snipers-first-70-buyers)和[合约检查](https://docs.gmgn.ai/index/ca-security-checks)用于核对字段含义。[Fomo 的持仓观点](https://help.fomo.family/en/articles/14436863-posting-a-thesis)说明内容来自用户发帖及持仓。Frank 沿用自己的视觉标识和既有数据，逐项对齐可复算的查询项目。

| 查询项目 | 页面及交互 | 免费来源与计算 | 实施完成条件 |
| --- | --- | --- | --- |
| 精确搜索与摘要 | 粘贴完整 Solana 地址，快速看到名称、代币符号、复制地址、安全要点和时间。 | 既有链上 Mint 读取、SPL/Token-2022 元数据、已接行情的币对信息。唯一键是链及完整 Mint。报价侧同样识别目标币。 | 同名不同 CA、错链、钱包地址、历史报告与当前输入切换均正确。名称不重复。 |
| K 线、成交量和市场状态 | 首屏价格、涨跌、流动性、成交量。K 线可选池、切周期、查看单根价格和量。市值有可信流通供应口径才显示为市值；其余按来源标明估值口径。 | DexScreener 现有币对行情做快照，既有 GeckoTerminal 公开接口按池读取 OHLCV。使用目标 Mint、池和计价方向。目标币在报价侧时采用已核实的目标币价格字段。 | 正向/反向、无池、源返回空、跨池切换及延迟响应都有用例。与公开页面比对同池、时段和单位。历史数据带时点，里程碑不以能画出图为完成。 |
| 近期成交与交易者 | 逐笔列时间、买卖方向、价格、数量、发起地址、原交易，按方向和地址筛选。交易者页汇总所读窗口的公开成交；未知地址单独说明。 | GeckoTerminal 现有公开交易接口提供单池最近 24 小时最多 300 笔。用来源事件身份去重，签名下多腿按实际序号保留；以目标币实际方向取数量与价格。同币多池切换。 | 标明覆盖池和实际最早/最晚记录、不把该接口当完整市场历史。来源饱和时继续保留独立完整路径，交易者榜不暗示跨链钱包盈利或平台标签。 |
| 持有人、前十和池 | 看持有人数、已核实的前十大持仓、份额、主要池和原始储备；点开看排除规则和账户全集。 | 既有 Solana RPC 精确读取两类代币程序，按 Owner 整数聚合，对齐供应分母和观察时点；按协议核对池和 Vault；由证据排除已确认的池、CEX、锁仓。 | 同一地址不重复计；原始余额和角色保留。只取得已知地址的第二来源读数时视为余额对照。全局和独立集合各有证据；不足只呈现能核实的口径。 |
| 开盘买家、开发者和可核风险 | 显示开盘前 70 名、早期买入/当前余额、开发者、狙击和疑似捆绑证据。查看 Mint/冻结/更新权限、已知扩展、LP 锁或烧及风险根据。 | 既有链上发行与池槽位、连续签名证据、原交易及确认区块顺序。能证明起点时直接定位；否则完整翻页。有交易原件才跟踪买卖。 | 覆盖开盘转池、同槽截止、临时账户、无验证 LP、Token-2022。标签有计算范围。余额减少、共用公共付款人、市场标签均不直接证明卖出、共控或官方行为。 |
| 中文叙事与合约认领 | 首屏一段中文回答「这个币为什么被关注」，能点原帖、作者和时间。认领单独一行。点击才看引用、回复、来源链和原文。 | 现有链上元数据、项目官网、可公开访问的原帖与引用。已有中文事实优先。翻译使用本地或浏览器已有免费的能力，须保持原件；浏览器语言包缺失时也有中文状态和可回查出处。 | 至少分别核对真实引用/回复、仅提及、明确认领、同名错配及来源不可读。Musk 互动只有结构化原帖证据才标互动。没有认领仍展示可信叙事。未知原始内容不编中文故事。 |
| 钱包、首买、资金及关系 | 从持有人或开盘行点开指定钱包，显示首次取得／首次已证实买入、买入前资金、能支持的关系。完整尽调仍可查后续历史。 | 已有钱包及代币账户原件、分段分页、源空页、旧检查点。SOL/WSOL/USDC 原币资金分别核对。已核金库保留余额，免扫个人历史。 | 多账户钱包不遗漏。关闭账户全集不足只影响声明范围；公共设施不升格共控。复杂、关联和无关反例都需要，深查不改变查询状态或通知。 |

**平台数据边界。** GMGN 的标签和覆盖有自己的数据与规则；Fomo 持仓观点来自平台用户。Frank 用能核实的本地证据给出相应类别，结果缺证时保留该字段的范围。复用已有免费来源，不依赖 GMGN 私有接口、付费升级或平台访问限制的规避。行情与逐笔来源依据见 [DexScreener 接口](https://docs.dexscreener.com/api/reference)和[现有 GeckoTerminal 公共接口](https://api.geckoterminal.com/docs/v2/swagger.json)。

以下是重做合同，用于实现与验收。路径为既有入口或拟采用的最小映射，先检查能否复用已有服务，避免同一事实两套实现。

| 阶段 | 入口及最小输出 | 可见验收 |
| --- | --- | --- |
| 1. 买入与通知准入 | 从现有流水和 Scanner 事实投影出 `人物、钱包、链、完整 Mint、签名、槽位、时间、买入数量、原币对价、证据状态`。列表支持按时间与 Mint 筛选及稳定分页。资格和审计通过既有路径接入。 | 反查表 S01–S10。截图中冗余项消失，历史价不触发查询。正例进入列表，BP/非 Meme/被动/失败/未知不进入买入页或模拟邮件。以独立真实钱包区间核对漏报、误报和时延。 |
| 2. 查询首屏与市场 | 复用 `POST /api/cluster-analysis` 的摘要任务、对应 GET 及按任务归档；查询中的分池行情和成交提供明确的 `Mint、pool、周期、币种、观测时间、覆盖、记录`。新读入口绑定已确认的 CA/池及报告，不接受任意外部地址。 | 反查表 C01–C07、C11–C12。中文叙事、认领、同池 K 线与近期成交可用；无数据时仍能读已有结果。验证跳池/换币迟到响应无法覆盖当前页面。 |
