**与现有文件的关系：**

## 0. 结论先行

1. 问题不是“文档不够细”，也不是“止损线不够多”。仓库里已经有大量门禁、ADR、止损和 NO_GO，但进度仍然很少。
2. 根因有四条：
   - **目标没有进入状态文件。** 项目目标是“扣费后可执行净收益”，但各模块的状态文件和 PR 标题里几乎没有这个指标。
   - **止损只会刹车，不会推进。** 门禁说“不能过”，却没有任何机制强制给出“现有数据下的答案”。
   - **工作以 PR 和过程产物增长，而不是以业务结论增长。** 仓库内当前有 199 个 Open PR，其中 101 个标题含 “frank”，主线合并的 PR 总数只有 22（见第 1 节证据）。
   - **状态和决策存在于聊天记录里。** 每次新对话都要重新对齐，关键裁决没有可追溯的登记。
3. 本方案用六件可执行的东西替代“更厚的文档”：
   1. 北极星指标与经济门禁阶梯（G0–G6），每一步都有明确的数据要求和分母。
   2. 每模块一个 `STATUS.md`，作为唯一状态来源；全局 `DECISION_LOG.md` 记录所有裁决。
   3. 预算与止损矩阵，每个阈值都对应一个**强制动作**，动作包含“必须给出答案”。
   4. 分层测试方案（L0–L6），每层写明能证明什么、不能证明什么。
   5. 与 ChatGPT 网页端对话的固定协议：开场读取、单次只推进一个门禁、结束输出固定状态块。
   6. 一个只读的治理检查脚本（第 12 节，待批准后实施），把“是否超预算、是否过期、是否有未登记决策”变成机器可查的结果。

### 1.1 对“妖币有止损线，为什么也没进度”的直接回答

有止损线，问题不在于没有。Monster 的失败模式是：

> 门禁不过 → 补数据 / 补验证 → 新门禁不过 → …… 每一步都正确，但答案永远在下一步。

因此，本方案在止损之外增加了**油门规则**（第 4.1 节）：到期时必须用现有数据给出 `GO` 或 `NO_GO`，不允许以 `NEED_MORE_DATA` 结束阶段。同时增加**成本指标**（cost-to-answer）：衡量“得到答案花了多少时间、请求和 PR”，而不是只看“通过了多少验证”。

### 1.2 漂移的具体信号（可以用来自检）

- 连续 3 个 PR 没有新增任何真实数据点或业务结论。
- 一个模块的 Open PR 超过 3 个。
- 状态文件里出现了本方案词表之外的状态词。
- 一个阶段超过预算天数仍然没有结论。
- 某次对话的结论没有写入 `DECISION_LOG.md`。

## 2. 唯一目标与成功定义

### 2.1 北极星问题

> **在扣除全部成本（手续费、滑点、路由费、延迟损失）之后，按照可执行报价成交，跟随指定链上钱包的买卖是否显著优于预先定义的随机对照？**

拆分为三个必须分别回答的子问题（对应用户目标的三条）：

1. **及时性**：能否在可接受延迟内发现目标钱包本人签名的真实 BUY/SELL？
2. **可执行性**：在 60 / 300 / 900 秒延迟下，合理规模的纸面交易能否以可成交报价执行？
3. **净收益**：扣费后的收益是否优于实时随机对照组？

### 2.2 指标分母规则（强制）

任何数字都必须同时写出分母。以下区分不得混用：

| 层级 | 名称 | 含义 | 禁止误用 |
|---|---|---|---|
| L-a | `SIGNED_TX` | 目标钱包作为 `from` 发出的交易 | 不得当作买入 |
| L-b | `SWAP_CANDIDATE` | 调用已知 Router 或选择器命中的交易 | 地址命中不等于成功 swap |
| L-c | `BUY_CONFIRMED` / `SELL_CONFIRMED` | 交易成功，且收据或状态变化支持方向 | 必须有收据证据 |
| L-d | `EXECUTABLE_QUOTE` | 在指定延迟可获得的可成交报价 | V2 `getAmountsOut` 不等于 V3 或聚合器价格，更不等于成交 |
| L-e | `NET_PNL_AFTER_COST` | 扣费后的纸面收益 | 缺任一成本项则为 `UNRESOLVED` |

**规则：** 对照组也必须用同一分母定义，不能用“对照有 N 笔、目标有 M 笔”的口头比较。

## 3. 经济门禁阶梯（G0–G6）

所有模块使用同一套门禁名称。门禁只有两个阶段结论：`GO` 或 `NO_GO`。进行中可以写 `IN_PROGRESS`，但不得作为阶段结论。

| 门禁 | 名称 | 回答的问题 | 进入条件 | 退出证据（必须） | 默认预算 |
|---|---|---|---|---|---|
| G0 | 冻结 | 北极星、数据源、信号定义、对照组定义、预算、止损是否已固定 | 用户批准本方案 | `STATUS.md` 与 `DECISION_LOG.md` 登记；所有参数哈希化 | 3 天，0 外部请求 |
| G1 | 数据可得性 | 真实数据能否在目标延迟下取得，覆盖率与缺失分母是多少 | G0 通过 | 真实或 fake 测量的吞吐、积压、缺块、失败数；原始证据哈希 | 按许可执行，单次运行 |
| G2 | 信号正确性 | 候选事件能否被可复核地分类为 L-a/L-b/L-c | G1 `GO` | 分类表，附 UNRESOLVED 数量与分母 | 离线为主 |
| G3 | 可执行性 | +60/+300/+900 秒是否有可成交报价，含滑点与费用 | G2 有确认事件 | 报价快照、报价源、失败分母 | 另需许可 |
| G4 | 扣费后净收益 | 目标组相对随机对照组的成对差异是否为正，且置信区间不跨 0 | G3 有足够样本 | 预注册的分析计划；成对结果；CI；敏感性分析 | 离线 |
| G5 | 小额实盘 | 用户授权的小额真实跟单是否与纸面结论一致 | G4 `GO` 且用户授权 | 成交记录、成本、与纸面结果的偏差 | 金额由用户定 |
| G6 | 持续运行 | 长期运行是否稳定 | G5 结果可接受 | 运行日志、故障记录 | 另需授权 |

### 3.1 每一门禁的硬规则

- **G0 之前不得进行任何真实网络请求。**
- **一次 30 分钟或 5 分钟的前台采集 ≠ 24–48 小时观察。** 短运行只能给 `FEASIBILITY`，不能宣称门禁通过。
- **G4 的分析计划必须在看数据之前提交。** 一旦看过结果再改阈值，结论自动降为 `NO_GO`（失去预注册资格）。
- **任何门禁不得因为“再多收集一点”而无限延期。** 到期规则见第 4 节。

### 3.2 各模块当前位置（按已核实事实映射）

| 模块 | 当前门禁 | 最近结论 | 说明 |
|---|---|---|---|
| BSC F0（前向跟单） | G1 | 未取得有效测量 | 唯一一次 5 分钟运行只发出 1 个请求即失败，`blocks=0`；无连续区块数据，G2 未开始 |
| Frank | 按 PR 标题判断在 G1–G3 之间 | 尚无扣费后净收益结论 | PR #235 标题为 `DATA_NOT_SCORABLE`；PR #240 为 G4 前向可报价性协议，未合并。**需用 STATUS 文件核实，不以标题为准** |

## 4. 预算、止损与油门

### 4.1 油门优先于刹车：到期强制出答案

每个门禁都有预算。预算到期时，负责 AI 必须在 24 小时内给出结论，只允许 `GO` 或 `NO_GO`。

| 到期情形 | 强制动作 | 禁止 |
|---|---|---|
| 门禁预算到期，证据不足 | 用现有数据给出 `GO` 或 `NO_GO`，并写明置信度与最大盲点 | 以 `NEED_MORE_DATA` 结束；申请自动续期 |
| 数据来源持续失败 | 结论为 `NO_GO`（该来源），并给出：下一个最便宜的替代来源 + 其成本 + 放弃条件 | 只写“来源不稳定” |
| 真实运行中途失败 | 停止，记录实际请求数与未知结果数，写入 `INCIDENT` 条目 | 自动重跑；用新 nonce 续跑 |
| 样本为 0 | 结论写明“无事件可评估”，并判断是来源问题、信号问题还是钱包本身无交易 | 解释为“钱包不盈利” |

**`NEED_MORE_DATA` 只允许出现在门禁进行中的状态说明里，不允许作为阶段结论。** 用户可以直接拒收任何以它结束的阶段报告。

**答案为 NO 也是进度。** 本方案的核心效率指标是 cost-to-answer，而不是答案是否正面。

### 4.2 止损矩阵（所有阈值为建议值，需用户批准）

| 维度 | 阈值 | 触发动作 |
|---|---|---|
| 日历 | 门禁超过预算天数 | 24 小时内强制给出 `GO`/`NO_GO`（4.1） |
| 无进展 | 模块 14 天内没有任何门禁状态变化 | 召开决策（写 `DECISION_LOG`），用户选择继续、转向或终止 |
| 真实请求 | 任一 UNKNOWN 结果，或请求超出许可 | 立即停止；不得重试；写 `INCIDENT` |
| 连续失败 | 同一来源连续 3 次请求失败 | 结束本次运行；结论 `NO_GO`（该来源） |
| 连续 PR | 同一模块连续 3 个 PR 未新增真实数据点或业务结论 | 下一个 PR 必须是 A 类（见 5.2），否则拒绝合并 |
| PR 数量 | 单模块 Open PR > 3 | 冻结新 PR，先做分类与关闭 |
| 状态词 | 出现本方案词表之外的状态词 | 审核判定为 REQUEST_CHANGES |
| 决策留痕 | 对话中做出的裁决未写入 `DECISION_LOG` | 视为未生效 |
| 经济结论 | G4 的 CI 上界小于 0 | 该信号族 `NO_GO`；不得通过调参重开，除非重新预注册 |
| 资金 | 由用户在 G5 授权中定义 | 超出即停，无自动续作 |

### 4.3 状态词表（封闭集合）

- 阶段结论：`GO`、`NO_GO`
- 进行中：`IN_PROGRESS`、`BLOCKED_BY_AUTH`（需要用户授权）、`BLOCKED_BY_EVIDENCE`（缺证据）
- 测量状态：`MEASURED`、`NOT_MEASURED`、`UNRESOLVED`（仅用于分类结果）
- 事件分类：`SIGNED_TX`、`SWAP_CANDIDATE`、`BUY_CONFIRMED`、`SELL_CONFIRMED`、`UNRESOLVED`
- 代码状态（链上）：`NO_CODE_AT_SAMPLED_BLOCK`、`HAS_RUNTIME_CODE_AT_SAMPLED_BLOCK`、`RPC_ERROR_AT_SAMPLED_BLOCK`、`TRANSPORT_FAILED_AT_SAMPLED_BLOCK`、`NOT_CHECKED`

任何其他词都视为新状态，需要先写入 `DECISION_LOG`。

## 5. 工作分类与 PR 纪律

### 5.1 工作的三类（取代旧的 `[A]/[B]/[C]` 解释，与 PR #241 保持一致）

| 类别 | 定义 | 示例 | 默认优先级 |
|---|---|---|---|
| A | 直接改变门禁结论的产出 | 真实数据测量、分类结果、报价快照、预注册分析 | 最高 |
| B | 为 A 类提供前提 | 修复影响测量的 bug、只读观察器、必要的测试 | 只为具体 A 类任务服务 |
| C | 与当前门禁无关 | UI 美化、流程文档扩写、非阻断的审计、历史归档整理 | 默认不做 |

**硬规则：**
- 每个 PR 标题或首段必须标注 A/B/C，并引用对应的门禁编号。
- C 类 PR 在当前门禁未 `GO` 时**不得开启**。
- B 类 PR 必须引用一个具体的 A 类任务编号；否则按 C 类处理。
- 审核者发现分类错误，视为 P1。

### 5.2 PR 生命周期

- 新 PR 必须登记在对应模块 `STATUS.md` 的“进行中”中；未登记的 PR 不得合并。
- 14 天无更新的 Draft PR，由负责 AI 在状态文件中给出“继续 / 关闭 / 合并为历史归档”的建议，由用户裁决。
- 不允许通过新建 PR 来绕过已有的冻结 PR。
- 历史归档分支不作为状态来源，需在 `STATUS.md` 的“已关闭”中注明。

## 7. 测试方案（分层，每层写明证明范围）

| 层级 | 名称 | 运行位置 | 网络 | 证据 | 能证明 | 不能证明 |
|---|---|---|---|---|---|---|
| L0 | 静态与 Git 校验 | 任意 | 无 | SHA、blob、工作树是否干净、文件哈希 | 代码字节与审核对象一致 | 功能正确 |
| L1 | 离线单元测试 | 任意 | 无 | 完整测试日志与 SHA256，零 SKIP | 逻辑在给定输入下正确 | 真实链上行为 |
| L2 | fake transport 集成 | 任意 | 无（注入假传输） | 场景矩阵结果：延迟、截断、断连、并发 | 调度、超时、持久化与并发约束 | 真实节点性能 |
| L3 | 本机无网压力测试 | 用户 Mac | 无 | 同 L2，附机器信息 | 本机环境下的调度与磁盘行为 | 外部来源行为 |
| L4 | 一次性真实只读运行 | 用户 Mac | 仅许可范围内 | 许可 SHA256、逐请求账本、RAW 哈希、对账 | 该时段、该来源的真实可得性 | 持续可用性、盈利 |
| L5 | 纸面回放与分析 | 任意 | 无 | 预注册分析计划、结果哈希 | 在已采集数据上的净收益估计 | 未来收益 |
| L6 | 用户授权的小额真实运行 | 用户 | 用户授权 | 成交与成本记录 | 实际执行结果 | 长期稳定性 |

### 7.1 测试纪律

1. **每个 PR 必须声明它覆盖哪几层**，未覆盖的层写 `NOT_RUN` 并说明原因。
2. **零 SKIP 是合并条件。** 有 SKIP 必须写原因，且 SKIP 的测试不计入通过。
3. **CI 绿色 ≠ 门禁通过。** CI 只证明 L0/L1/L2 在该环境下通过。
4. **测试数必须与固定 SHA 绑定。** 不得复用旧 SHA 的测试数字。
5. **fake transport 的延迟数字不得当作真实延迟。** 报告中必须标注 `SIMULATED`。
6. **严禁为了通过测试而修改门禁阈值。** 阈值变化只能通过 `DECISION_LOG` 登记。

### 7.2 BSC F0 的最小测试矩阵（为下一次真实许可准备）

| 场景 | 层级 | 预期 |
|---|---|---|
| DNS 3 秒、6 秒延迟 | L2 | 超时后结算 UNKNOWN，不接受迟到结果 |
| 快速 RPC 响应 | L2 | 正确记录 RID、耗时、RAW 哈希 |
| 连接中断 | L2 | 不重试，记录 UNKNOWN |
| 响应截断、Content-Length 冲突 | L2 | 不计入有效 RPC |
| 三槽并发、POST 间隔 ≥ 250 ms | L2 | 实际启动间隔满足约束 |
| 缺块后的父哈希连续性 | L2 | 不得把跨缺口区块计为连续 |
| 首块父哈希 | L2 | 不得宣称已锚定，除非有独立锚点 |
| 真实节点吞吐 | L4 | 仅在许可下测量，结论只针对该时段 |

## 8. 证据规则

1. **私有原始数据**（RAW 响应、钱包交易明细、permit、nonce、账户信息）只保存在用户 Mac 的受控目录，**不得放在 `/tmp`**（`/tmp` 不是长期存储）。目录权限 0700，所有权为当前用户。
2. **GitHub 只提交脱敏内容：** 汇总统计、哈希清单、测试日志哈希、结论与分母。
3. **每份证据必须有哈希清单。** 哈希清单本身也要有 SHA256。
4. **原始证据不得覆盖。** 追加写入新文件，旧文件只读保留。
5. **结论必须能被第三方用哈希复核。** 无法复核的结论标注 `UNVERIFIED`。
6. **交接摘要不是证据。** 摘要中的数字必须回到原始文件核对，核对不了就标注为转述。

## 9. 与 GPT 网页端对话的协议

### 9.1 角色分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| 用户 | 所有裁决、授权、预算、金额 | 逐行审代码 |
| GPT 网页端 | 规划、决策卡草拟、独立复核 Codex 给出的证据摘要 | 直接运行网络请求 |
| Codex（Mac 本地） | 运行测试、执行已授权的命令、生成证据与状态更新 | 自行批准自己的结论 |

交叉审核方式按用户既定规则：Codex 本地执行 + 网页端复核脱敏证据。不寻找第三方 AI 作为批准者。

### 9.2 每次对话的开场

每次新对话开始时，粘贴以下固定开场：

```text
读取以下内容，然后只回答三件事：当前门禁、下一步唯一动作、需要我裁决的事项。
1. docs/governance/MODULE_STATUS/<模块>.md
2. docs/governance/DECISION_LOG.md 的最后 5 条
3. 本次要推进的门禁编号
不要重新讨论已经 DECISION_LOG 中裁决过的事项。
```

### 9.3 每次对话的结束

结束时必须输出以下状态块，并由用户决定是否写入仓库：

```text
模块：
门禁：G<n>，状态：
本次做了：
本次证据（哈希）：
预算使用：请求 X/Y，PR Z/3，天数 D/预算
是否触发止损：是/否（触发项）
下一步唯一动作：
需要裁决：DC-待编号 / 无
```

### 9.4 对话纪律

- **每次对话只推进一个门禁。**
- **一个对话超过约 60 轮，或开始重复已经裁决的问题时，必须开新对话**，用状态块作为开场。
- **用户不必读完全部文件。** 用户只需要看状态块和决策卡。

### 9.5 决策卡格式（用户 10 分钟裁决）

```markdown
## 决策卡 DC-YYYYMMDD-NN
问题（一句话）：
选项 A（推荐）：内容 / 成本（请求数、天数、PR 数、金额） / 放弃条件
选项 B：内容 / 成本 / 放弃条件
选项 C（终止）：内容 / 影响
我的推荐与理由（两句话）：
用户裁决：A / B / C / 其他
```

## 15. 坦白：流程解决不了的事

1. **流程不能保证 AI 不漂移。** 它只能让漂移变得可见，并把裁决权留给用户。
2. **用户的裁决成本是真实存在的。** 本方案刻意把每次裁决压缩到决策卡的格式，但仍然需要用户每周花时间。
3. **市场不一定存在可盈利的 edge。** 本方案的目标是尽快得到 `GO` 或 `NO_GO`，而不是保证 `GO`。
4. **免费公共数据源可能根本不足以支撑毫秒级或秒级跟单。** 这一点只能由 G1 的真实测量回答，不能用文档假设。
